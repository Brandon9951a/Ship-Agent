# 绿航智算：船舶能效管理智能体

绿航智算面向纯电动内河船舶的航行决策场景，结合自然语言交互、结构化工具和约束校验，辅助船员制定航速与能量管理方案。

项目以“豫交投001”及平顶山港—周口港航线为主要研究对象，参加 2026 AIC 算法创新赛的 AI+场景创新赛道。

## 项目目标

通过自然语言输入航行任务，完成以下流程：

```text
任务理解 → 数据获取 → 航段划分 → 能耗预测
        → 航速优化 → 能量管理 → 可解释报告
```

主要解决以下问题：

- 航速、到达时间、能耗与电池安全约束难以协同处理。
- 船员需要逐项配置参数，操作成本较高。
- 自然语言模型生成的工程数值缺乏可靠依据。
- 不可行任务需要明确原因，并支持用户选择调整方向后重新计算。

## 技术原则

- 大语言模型负责语义理解和解释。
- Python 计算工具负责航速、能耗、SOC、ETA 和功率等工程数值。
- 工具输入输出采用结构化数据。
- 规则负责硬约束、安全边界和数值一致性校验。
- 不可行任务必须返回原因，不生成虚构的可行方案。
- 调整选项由工具试算，用户选择后重新求解。

## 技术路线

计划采用：

| 部分 | 技术与职责 |
|---|---|
| 流程编排 | LangGraph：状态、节点、条件分支及人工选择 |
| 模型服务 | 可配置的云端大模型 API |
| 计算工具 | Python：数据处理、能耗预测、航速优化及能量预算 |
| 数据与配置 | 船舶事实、航线、限制条件及模型参数 |
| 交互界面 | Gradio 文本输入、结果表格与曲线 |
| 验证 | 自动测试、场景演示及可复现实验 |

模型服务与计算工具独立。应用和计算工具在本地运行，模型推理通过 API 调用。

## 五工具链

```text
Tdata → Tseg → Tenergy → Tspeed → Tmanagement
```

| 工具 | 目标职责 |
|---|---|
| Tdata | 获取任务所需数据，记录来源、缺失与冲突 |
| Tseg | 根据航线及活动约束划分航段 |
| Tenergy | 预测候选航速对应的功率与能耗 |
| Tspeed | 判断可行性并搜索满足约束的航速方案 |
| Tmanagement | 计算 SOC 轨迹、能量预算、告警和补能需求 |

## 安装与运行

要求 Python 3.10 或以上。

在仓库根目录中执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

运行状态入口：

```powershell
.\.venv\Scripts\python.exe main.py
```

运行五工具占位流程：

```powershell
.\.venv\Scripts\python.exe -m core
```

运行测试：

```powershell
.\.venv\Scripts\python.exe -m pytest
```

当前依赖支持工程骨架。业务依赖将随模块实现统一添加。

## 协作流程

1. 从最新 `main` 创建任务分支。
2. 在任务分支开发并完成相关测试。
3. 提交修改，写明具体内容。
4. 推送分支并创建 Pull Request。
5. 审查通过后合入 `main`。
6. 其他成员同步更新。

分支名称示例：

```text
feature/agent-flow
feature/energy
feature/route-data
feature/ui
fix/soc-validation
```

每个 Pull Request 应说明：

- 修改内容与目的。
- 测试方法及实际结果。
- 接口或配置变化。
- 已知限制和待解决问题。

公共数据结构与依赖由 A 统一维护。涉及数值和安全约束的修改由 B 参与复核。

五工具开发以接口契约和 schemas 为第一依据，B/C 统一使用其字段、单位与返回状态。A 已授权助手完成本次接口复审并直接更新 main；B/C 的模块工作仍按任务分支与 PR 流程提交。参数采用、范围和接口变更由 A 决定，助手负责实现与测试。

## 本周验收场景

- 正常可行任务：输出航速、到达时间、能耗和 SOC。
- 时间不可行任务：解释原因，支持选择调整后重算。
- SOC 不足任务：拒绝不安全方案，提供工具试算支持的调整建议。

同时覆盖缺参追问、子航线与返程、错误停止、模型服务失败等情况。

## 数据与凭据管理

仓库保存源码、配置样例、测试和必要的小型示例数据。

大型原始航行数据、展示素材和视频通过团队资料包共享。公开分享的数据应核实来源权限并按需脱敏。

真实 API 密钥通过环境变量配置，不提交到仓库。虚拟环境、缓存和生成的大型文件应加入 `.gitignore`。
