# Ship-Agent
# 绿航智算：船舶能效管理智能体

绿航智算面向纯电动内河船舶的航行决策场景，结合自然语言交互、结构化工具和约束校验，辅助船员制定航速与能量管理方案。

项目以“豫交投001”及平顶山港—周口港航线为主要研究对象，参加 2026 AIC 算法创新赛的 AI+场景创新赛道。

## 项目目标

通过自然语言输入航行任务，完成以下流程：

```text
任务理解 → 数据获取 → 航段划分 → 能耗预测
        → 航速优化 → 能量管理 → 可解释报告
```

主要解决以下问题：

- 航速、到达时间、能耗与电池安全约束难以协同处理。
- 船员需要逐项配置参数，操作成本较高。
- 自然语言模型生成的工程数值缺乏可靠依据。
- 不可行任务需要明确原因，并支持用户选择调整方向后重新计算。

## 技术原则

- 大语言模型负责语义理解和解释。
- Python 计算工具负责航速、能耗、SOC、ETA 和功率等工程数值。
- 工具输入输出采用结构化数据。
- 规则负责硬约束、安全边界和数值一致性校验。
- 不可行任务必须返回原因，不生成虚构的可行方案。
- 调整选项由工具试算，用户选择后重新求解。

## 技术路线

计划采用：

| 部分 | 技术与职责 |
|---|---|
| 流程编排 | LangGraph：状态、节点、条件分支及人工选择 |
| 模型服务 | 可配置的云端大模型 API |
| 计算工具 | Python：数据处理、能耗预测、航速优化及能量预算 |
| 数据与配置 | 船舶事实、航线、限制条件及模型参数 |
| 交互界面 | Gradio 文本输入、结果表格与曲线 |
| 验证 | 自动测试、场景演示及可复现实验 |

模型服务与计算工具独立。应用和计算工具在本地运行，模型推理通过 API 调用。

## 五工具链

```text
Tdata → Tseg → Tenergy → Tspeed → Tmanagement
```

| 工具 | 目标职责 |
|---|---|
| Tdata | 获取任务所需数据，记录来源、缺失与冲突 |
| Tseg | 根据航线及活动约束划分航段 |

| Tspeed | 判断可行性并搜索满足约束的航速方案 |

## 安装与运行

要求 Python 3.10 或以上。

### Render 在线部署

仓库根目录提供 `render.yaml`，可在 Render 中选择 **Blueprint** 并连接本仓库完成部署。默认使用新加坡区域、1 CPU / 2 GB 实例，并通过 `/healthz` 检查服务状态。

首次部署时填写 `SHIP_LLM_API_KEY`。云端定性理解默认启用；密钥缺失、配置无效或调用失败时，系统自动回退到确定性五工具计算与模板说明。真实 `.env` 不得提交到仓库。

如需启用页面中的科大讯飞语音输入，在 Render 服务的 **Environment** 中另行添加 `XFYUN_APPID`、`XFYUN_API_KEY`、`XFYUN_API_SECRET`，然后重新部署。三个值只保存在服务端，浏览器只会收到语音服务是否可用的状态。任一值缺失时，麦克风按钮保持禁用，但不影响文本输入和五工具计算。`XFYUN_IAT_URL` 已在 Blueprint 中固定为安全 WebSocket 地址。

也可以手动创建 Web Service：

```text
Build Command: pip install -r requirements.txt
Start Command: python -m ui.web_server --host 0.0.0.0 --port $PORT --llm
Health Check Path: /healthz
```

### Windows 本地驾驶舱演示

完成依赖安装并在仓库根目录配置好本机 `.env` 后，双击
`start_local_demo.cmd`。启动器会检查依赖和端口、执行一次不输出密钥与原始内容的
DeepSeek 最小连通测试，然后启动 `http://127.0.0.1:8765` 并打开浏览器。模型连接
失败时仍会启动确定性五工具链，并在定性说明处显示模板回退。

本地页面支持自然语言与结构化输入，并展示五工具状态、航段、航速、ETA、能耗、
SOC、来源和风险。所有成功结果均标记 `synthetic_demo`，不代表实船安全或运营批准。
端口 8765 被占用时启动器只提示冲突，不会结束其他进程。

在仓库根目录中执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

运行状态入口：

```powershell
.\.venv\Scripts\python.exe main.py
```

运行五工具占位流程：

```powershell

```

运行测试：


## 协作流程

1. 从最新 `main` 创建任务分支。
2. 在任务分支开发并完成相关测试。
3. 提交修改，写明具体内容。
4. 推送分支并创建 Pull Request。
5. 审查通过后合入 `main`。
6. 其他成员同步更新。

分支名称示例：

```text
feature/agent-flow
feature/energy
feature/route-data
feature/ui
fix/soc-validation
```

每个 Pull Request 应说明：

- 修改内容与目的。
- 测试方法及实际结果。
- 接口或配置变化。
- 已知限制和待解决问题。

公共数据结构与依赖由 A 统一维护。涉及数值和安全约束的修改由 B 参与复核。

五工具开发以接口契约和 schemas 为第一依据，B/C 统一使用其字段、单位与返回状态。A 已授权助手完成本次接口复审并直接更新 main；B/C 的模块工作仍按任务分支与 PR 流程提交。参数采用、范围和接口变更由 A 决定，助手负责实现与测试。

## 本周验收场景

- 正常可行任务：输出航速、到达时间、能耗和 SOC。
- 时间不可行任务：解释原因，支持选择调整后重算。
- SOC 不足任务：拒绝不安全方案，提供工具试算支持的调整建议。

同时覆盖缺参追问、子航线与返程、错误停止、模型服务失败等情况。
