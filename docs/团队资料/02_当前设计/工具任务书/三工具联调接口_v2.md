# Tenergy—Tspeed—Tmanagement 联调接口 v2（研究系统目标契约）

> 状态：供三位负责人按同一格式实现和联调的目标契约；尚未落入 `schemas/types.py`，不得宣称当前演示系统已支持。版本记为 `research-tools/2.0-draft`，冻结字段后升为 `research-tools/2.0`。本文由三份任务书共同引用。
> 旧[五工具接口契约](../../../接口/五工具接口契约.md)及 `schemas/types.py` 是现行演示接口；其中“固定候选能耗表、分段平均功率、合并容量/SOC”和“模型只负责解释”不适用于目标研究系统。迁移须显式转换或返回不支持，不能把旧数据悄悄解码为 v2。

## 1. 三工具共同不变量

| 项目 | v2 约定 | 不满足时 |
|---|---|---|
| 时间 | 规划基准时刻 `planning_origin_at` 使用带时区 ISO 8601；未取得绝对时刻时为 `null`，所有时序用自基准起的 `start_offset_s` 和 `duration_s`（秒） | 时间非单调、重叠或间隙未解释则 `invalid_input`；没有绝对时刻时不得给出日历 ETA |
| 区间 | 每个样本表示 `[start_offset_s, start_offset_s + duration_s)`，`duration_s > 0`；候选可有不同长度或时长 | 不用数组下标假定不同候选在同一时刻 |
| 距离与速度 | 内部 km、km/h；源数据的节按 `1 kn = 1.852 km/h` 显式转换；加速度内部 m/s² | 单位或转换依据缺失则拒绝相应检查 |
| 功率与电量 | kW、kWh；按 `Σ P_k × duration_s / 3600` 积分；每个功率字段写测量边界和口径 | 电机侧与母线侧不能直接相加或比较限值 |
| 两组电池 | `battery_1`、`battery_2` 独立提供有效容量 kWh、SOC 0–1、规划下限、功率上限、效率/损耗模型及来源 | 任一必需参数未知时不能输出完整双电池安全方案 |
| 来源与情景 | 采用值关联 `source_ref`；回放、仿真、实船按字段标记；假设记录 `assumption_id` 及取值，不用未知值冒充零或实测 | 缺关键来源时返回缺参或仅运行显式标注的研究情景 |
| 版本与关联 | 每次请求含 `schema_version`、`task_id`、`request_revision`、`snapshot_id`、`scenario_id`、`call_id`；输出回显相应 ID、算法/模型/配置版本及输入哈希 | 来源或版本不一致不得合并为同一方案 |
| 结果工件 | 大型时序以 `artifact_id + sha256 + row_count + schema_version` 保存；返回可查询摘要和引用 | 不用省略明细的总计数冒充完整过程 |

5 秒是现有 Excel 的原始采样间隔，也是预测实验的初始候选值，**不是**已冻结的全航程规划步长。Tenergy 的推理步长、DE 的候选轨迹展开步长和 FDP 的状态转移步长可不同，但须定义有误差验证的重采样/积分算子。三工具的交接使用同一份带时间边界的需求时序，转换前后保存对应关系；最终入选轨迹在共同核验网格上重新计算。

上游入口也要升级：Tdata 或研究情景提供两组独立电池参数、当前位置/速度、设备状态及逐字段来源；Tseg 提供稳定的 `segment_id`、距离、限速、等待/停靠规则与来源。旧 Tdata 只有合并容量和 SOC 时，不得由三工具自行拆分；旧 Tseg 的分段平均 `waiting_h` 须由轨迹展开器明确放到时间轴上。主图集成者负责请求、快照、情景与方案版本关联，并在缺参时阻止生成完整安全方案。

## 2. 状态信封与失败语义

每次工具返回 `ToolRun`：`schema_version, tool_name, call_id, parent_call_id, input_hash, request_revision, snapshot_id, scenario_id, started_at, finished_at, execution_status, outcome_code, payload_ref, diagnostics[], model_or_algorithm_version, config_hash`。`execution_status` 只区分 `completed / failed / cancelled`；`outcome_code` 说明工程结果，至少支持：

| `outcome_code` | 判定边界 | 上层动作 |
|---|---|---|
| `ok` | 该工具按约定完成；不自动等于完整航行方案安全 | 读取 payload 和检查项 |
| `needs_input` / `invalid_input` | 关键事实缺失/冲突，或字段类型、范围、时序非法 | 获取或修正输入 |
| `model_out_of_domain` | LSTM 必需特征缺失或候选明显超出已验证适用范围 | 限域、补数据或停止正式预测 |
| `search_unresolved` | DE 在预算内未找到可行候选 | 记录预算与诊断；不得称数学无解 |
| `infeasible_under_assumptions` | 有明确约束证据且结论限于已记录模型/假设 | 重搜或协商；记录证明范围 |
| `tool_error` | 运行异常、超时、模型/工件不可用 | 有界重试；不得归因于电池不足 |

FDP 在给定离散网格上无路径时，写 `grid_unresolved` 诊断或 `infeasible_under_assumptions` 并限定为该网格与状态转移模型；不得扩展成实船全局不可行。每条 `diagnostics[]` 至少含 `stage, code, time_interval_or_segment_id, field_ref, observed, limit, unit, source_refs, retryable, detail`；未知值为 `null`。旧 `ToolResponse.status=infeasible` 须通过迁移层结合证据映射，不能直接等同 v2 的证明性分类。

## 3. Tenergy → Tspeed：批量预测

`EnergyBatchRequest` 包含上述信封标识及 `history_ref, environment_scenario_ref, model_version, integration_rule, candidates[]`。每个候选有唯一 `candidate_id` 和 `trajectory[]`；轨迹项至少有 `segment_id, phase`（航行/等待/停靠）, `start_offset_s, duration_s, planned_speed_kmh`（非航行阶段可为 0 或明确未知）, `environment_ref`。历史观测只截至规划起点；未来真实功率不得出现。不同候选可共享历史与环境情景，但未来变量应按该候选的位置和时间取值。

`EnergyBatchResult` 按 `candidate_id` 返回成功或诊断、逐时 `PowerPoint` 工件及航段/全程汇总。`PowerPoint` 至少有 `segment_id, phase, start_offset_s, duration_s, planned_speed_kmh, predicted_motor_power_kw, motor_energy_kwh, applicability_flag, quality_flags`。`motor_energy_kwh = predicted_motor_power_kw × duration_s/3600` 或采用已记录的积分规则；预测与积分区间须一致。汇总至少有预测电机侧推进 kWh、峰值电机 kW、有效覆盖率和异常/外推比例。负功率、等待阶段、无法预测区间按模型规则显式标记，不能默认为零。接口给出 `evaluate(...)` 和 `evaluate_batch(...)`，批量与逐条调用在相同输入下需数值一致。

批次、候选、模型版本、缓存命中及耗时分别可查。缓存键至少覆盖候选轨迹、历史窗口、环境情景、模型权重/归一化器及预处理版本；相同速度向量但不同水文情景不能误命中。

## 4. 电机侧 → 电池母线：单一转换位置

研究系统的共同需求时序为 `PowerDemandSeries`：每个区间记录 `motor_power_kw, propulsion_bus_kw, auxiliary_bus_kw, demand_bus_kw, conversion_model_ref, phase, start_offset_s, duration_s`。**Tenergy 只负责预测主推进电机侧功率。**电机到母线的转换和辅助负载合并由共享的需求构建适配器执行，Tspeed 的电池约束与 Tmanagement 必须读取这同一工件，不能各自暗算一次效率或各加一次辅助负载。

该适配器由 **Tspeed 负责人实现并交付独立模块**，Tenergy 负责人核对输入功率口径，Tmanagement 负责人核对输出母线边界与损耗，主图集成者负责从 Tdata 注入已确认参数或具名研究假设。适配器输出自身配置哈希、输入预测工件 ID 和来源，接受独立单步能量守恒检查；转换逻辑不藏在 DE 目标函数或 FDP 状态转移中。

转换模型可以来自核实设备参数；研究仿真可用具名假设。未得到转换依据时，`demand_bus_kw=null`，可继续做明确标注的电机侧航速对照实验，但不得宣称 SOC 安全或完整实船规划。推进、等待和补能阶段分别记录；负需求或回馈只在物理定义、设备能力与效率经核实后启用。

首版 FDP 的三模式是放电供能策略。若协商试算包含途中补能，须另外定义并验证充电状态转移、充电功率上限、效率、可用时间和两组充电分配；在该扩展完成前返回“不支持补能试算”，不得把负的 `demand_bus_kw` 当作已实现的充电模式。补能设施本身还需 Tdata/Tseg 的位置和停靠来源。

## 5. Tspeed → Tmanagement：选定轨迹与完整检查

`SpeedOptimizationRequest` 至少含路线及航段引用、当前速度/位置、剩余期限、目标类型、速度/加速度/时间/功率约束及来源、有效的 `EnergyBatch` 调用句柄、共同需求构建器、算法配置/随机种子、先前 FDP 反馈引用。目标类型只允许已实现的 `min_energy` 或 `min_time`；未实现时返回不支持，不能悄悄改用另一目标。

`SpeedOptimizationResult` 至少含 `search_status, selected_candidate_id, selected_trajectory_ref, selected_energy_ref, selected_demand_ref, segment_summary, total_duration_s, arrival_at, objective_terms, constraint_checks[], search_trace_ref, seed, population, generations, evaluations, runtime_ms`。`arrival_at` 在绝对基准时刻未知时为 `null`。所有最终选定轨迹以规定核验精度重跑 Tenergy 与需求构建器，并单独检查航段顺序、距离积分、限速、加减速、时间、同边界功率及有依据的预算；未通过则不得输出可执行选定方案。`search_status` 区分 `candidate_found / search_unresolved / input_invalid / model_out_of_domain / tool_error`。

`BatteryManagementRequest` 使用同一 `selected_demand_ref`、两个独立电池参数、初始 SOC、规划下限、允许模式/转换、FDP 网格与权重配置及来源。FDP 不接收孤立的分段平均能耗替代逐时需求。`BatteryManagementResult` 至少含 `safe, mode_trajectory_ref, battery_1_power_ref, battery_2_power_ref, battery_1_soc_ref, battery_2_soc_ref, cost_terms, constraint_checks[], diagnostic_ref, feedback_ref, runtime_ms`；逐时工件能复算需求平衡、SOC 转移、切换次数和最终汇总。`safe=true` 仅表示在给定来源、假设、网格与独立检查下通过。

## 6. FDP → Tspeed：受约束重搜反馈

失败反馈 `ManagementFeedback` 包含 `selected_candidate_id, selected_demand_ref, battery_config_hash, failure_scope, first_failure_interval, violated_rule, demand_kw, deliverable_kw, soc_1, soc_2, limit_source_ref, diagnostic_certainty, suggested_search_action`。仅在能够证明对候选族有效时，才生成新的硬功率或能量约束；例如某时段有来源的母线总功率上限。依赖此前 SOC 轨迹的失败不简化成对所有新轨迹都成立的局部功率上限，可作为候选拒绝记录、代价提示或下一次 FDP 复核依据。上层核验版本、来源与反馈适用域，再给 Tspeed 有界重搜；预算耗尽返回未解决或在已记录假设下不可行，不伪装成成功。

DE 不能对每个候选完整运行高成本 FDP；采用阶段预算筛选、对入选候选执行 FDP、失败后受限重搜。需要测量“预测次数、FDP 次数、可行方案率、耗时”，以决定是否需要更早的电池约束近似。

## 7. 联调入口、验收和迁移

1. 组员先共同冻结本文件的字段名、枚举、序列化、时序网格映射与样例，交付机器可读 schema 或 dataclass、合法/非法 JSON 样例及版本号；字段有变更同时更新三份任务书和适配器。
2. Tenergy 负责人给固定轨迹与情景的批量预测夹具；Tspeed 负责人在该夹具上得到可复现的选定轨迹；Tmanagement 负责人用同一 `selected_demand_ref` 复算两组功率、SOC 与反馈。至少覆盖一例完整成功、一例 FDP 拒绝并重搜、一例模型域外和一例缺转换依据。
3. 对每例保留 task/request/snapshot/scenario/model/config 哈希、调用父子 ID、工件哈希、算法种子、检查报告和耗时；相同输入重跑结果允许的数值容差须事先写明。
4. 旧接口通过明确的 v1→v2 迁移层供演示代码过渡。旧 `EnergyResult` 仅有分段平均值，不能逆推出逐时功率；旧 `ManagementPlan` 只有合并 SOC，不能拆成实测两组状态。缺少新接口必需信息时返回不支持或缺参，不以默认值补齐。
5. 最终由独立检查器在同一套工件上检查时间、距离、功率边界、能量积分及两组 SOC。工具自身 `feasible/safe` 不能替代检查器。接口契约验收与算法效果验收分别记录。

仍需三位负责人以实测/实验结果冻结的**参数值**：推理及 FDP 步长、长时滚动预测策略、规划网格、SOC 离散粒度、DE 种群与预算、效率/辅助负载的采用值、数值容差、模型适用域。字段和单位可先按本文件实现；参数值未知时保留空值或使用具名研究情景，不能填未经核实的实船默认值。
