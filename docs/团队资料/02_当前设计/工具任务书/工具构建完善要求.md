## 二、Tenergy：LSTM 能耗预测工具

**对象：`luoj5920-byte`；更新 PR #9。** 当前已提交三源数据清洗、条件式 LSTM、权重与留出评估。现有 `batch_evaluate` 仍是实验 API，模型清单中的 `planner_approved=false` 必须保留。来源留出集上，LSTM MAE 为 **1.029 kW**，持续功率基线为 **0.858 kW**；不能把“训练及代码完成”写成“正式规划预测器通过”。

### 具体完善任务

1. **补齐本工具的 v2 接口。** 提供以 `EnergyBatchRequest` 为输入的批量入口，按 `candidate_id` 返回逐候选状态；每个有效预测区间记录航段、阶段、相对起点、时长、计划航速、预测电机侧功率和积分电耗。提供 `ToolRun` 信封、模型及归一化器版本、输入/工件哈希、覆盖率和诊断。不同候选时长、批内换序及部分候选失败都要有测试。现有列表式实验输出不能直接冒充 v2 工件。
2. **守住模型和数据适用边界。** 正式规划模式遇到未批准模型时返回明确的 `model_unapproved`；缺历史、缺有来源的必需环境字段、候选超训练域、超过已验证预测时域、等待负载未知等情况分别返回可辨认的状态或诊断。等待、辅助负载和电池侧电耗没有依据时保持未知，不以零补齐。
3. **解释留出集负面结果。** 在相同划分、相同移动工况和相同指标下，分析 LSTM 与持续功率、速度—功率基线的差异；至少报告来源、速度区间、预测步长及滚动时域上的误差。检查跨来源分布差异和训练窗口覆盖。若现有三份数据不足以使模型通过门槛，保留负面结论，并列出下一轮所需数据及最小验证条件；不为追求“通过”而更换不可比口径。
4. **测量批量推理成本。** 除现有 100 个五步样例外，报告代表性候选数、候选时长、CPU/GPU、批量耗时和内存；给出模型加载及同输入重复调用的一致性结果。

### 在 PR 中提交的证据

- 可运行的 v2 接口、机器可读样例及自动测试；实验 API 与正式规划入口的差异说明。
- 冻结的数据划分和模型版本、复现命令、逐项基线对照、批量性能结果。
- `planner_approved` 的判定依据、尚未确认的单位/测量边界与需负责人裁决的问题清单。

**个人完成判据：** 本工具的批量时序输出和失败状态可独立复算；未批准模型不能被误用为正式优化依据。模型是否获得正式规划准入，按留出集和适用域证据单独决定，不要求用未经证实的数字填满接口。

## 三、Tspeed：DE 航速优化工具

**对象：`xukeyan666-cyber`；更新 PR #11。** 当前已提交 DE、轨迹展开、独立检查器、v2 契约草案和共同需求构建器。本轮自测的两个未解决问题是：DE 在同口径规则航速对照下比“各段最低航速”基线差约 **1.1%**；剩余 9 段滚动重规划返回 `search_unresolved`。当前解析功率后端属于仿真实验，不代表已接入获准 LSTM。

### 具体完善任务

1. **定位规则基线差异。** 让 DE 解和规则基线经过同一轨迹展开、相同功率后端、同一目标函数及独立约束检查。报告名义速度与实际展开速度、各项约束、能量及平滑惩罚分项、多随机种子和搜索预算。明确差异来自搜索收敛、边界修复、限速夹取、目标尺度还是基线口径；如仍无法定位，如实给出排查结果和未决证据。
2. **定位滚动重规划失败。** 固定剩余 9 段的输入、当前速度、剩余时间和随机种子，输出首个失败约束、违反统计、可行个体比例与诊断候选。修复实现问题时加回归测试；如果本次预算仍未找到方案，保持 `search_unresolved`，不声称数学无解。
3. **完善优化器自身的可复核性。** 保持目标函数、DE 搜索和独立约束检查分离；核对选定轨迹的速度、加速度、距离、时间、功率和能量积分。记录随机种子、种群、代数、预测次数、耗时、搜索轨迹及失败分类。未通过独立检查的候选不得进入选定方案字段。
4. **验证本人负责的共同需求构建器。** 用模块内夹具核对电机侧到母线侧转换、辅助负载只加入一次、`kW × s / 3600 = kWh`、配置哈希及来源记录。缺转换依据时母线需求保持未知，只能输出电机侧实验结论。共同采用的实际转换参数由项目负责人裁决，本工具不得暗设实船默认值。

### 在 PR 中提交的证据

- 两个负面结果的固定输入、运行命令、诊断输出、修复或未决分析及回归测试。
- 多种子求解质量、规则基线的同约束比较、计算预算和独立检查结果。
- 需求构建器合法/缺参样例、能量守恒测试及需要负责人裁决的参数清单。

**个人完成判据：** 优化器能在已声明的仿真后端上给出可复核的候选或诚实的未解决诊断；规则基线与滚动案例的结果有可复现解释。LSTM/FDP 实际接入及三工具整体安全判定不作为本人的单独验收项。

## 四、Tmanagement：FDP 双电池能量管理工具

**对象：`Lucien050303`；更新 PR #10。** 当前已提交双电池三模式 FDP、状态机、独立轨迹检查器和六类示例。PR 说明仍为模板；专项自动测试、穷举对照与全航程性能证据尚未随 PR 提交。样例运行成功不能替代算法正确性验证。

### 具体完善任务

1. **补独立正确性测试。** 在 2–4 时步的小例子中穷举所有合法模式路径，逐项比较 FDP 的最低总代价、四项成本、模式轨迹、两组功率和 SOC。覆盖单启、双启、零负荷、切换、单组过载、SOC 触底、网格预算耗尽及不支持充电。测试既检查输出值，也检查失败类别。
2. **验证独立检查器与失败语义。** 对所有 `safe=true` 轨迹复核功率平衡、单组功率界、两组 SOC 下限、时间及电量守恒。将有来源的瞬时总功率超限、依赖原候选 SOC 路径的失败和网格/算力未解决分别表述；在离散网格无路径时，不扩展为实船全局无解。
3. **补齐对照与敏感性实验。** 在相同需求、初始 SOC、容量、效率和约束下比较 FDP 与论文状态机；报告终点及最大 SOC 差、两组功率波动、模式切换次数、四项成本和约束违例。改变 SOC 网格与代价权重，报告结果稳定性、状态数、转移数、耗时和内存；再给出代表性全航程的性能记录。
4. **整理本工具的输入输出与证据边界。** 提供具名仿真电池参数、母线需求时序、成功与各失败类型的机器可读样例；说明电池效率只用于母线输出到电池能量变化，不在 FDP 内重复做推进电机到母线的转换或暗加辅助负载。历史 `capacity` 字段未经确认前，不把仿真 SOC 当实测标签。
5. **重写 PR 说明。** 用实际修改内容、运行命令、测试结果、实验表格和已知限制替换模板；对共同需求格式或反馈字段仍有疑问时列出具体字段和建议，由项目负责人统一决定。

### 在 PR 中提交的证据

- 专项自动测试和小规模穷举对照结果；独立检查器通过/拒绝样例。
- FDP 与状态机同口径对照、网格/权重敏感性、全航程资源开销。
- 参数来源及假设表、机器可读时序/反馈样例、完整 PR 说明。

**个人完成判据：** FDP 的选定路径在小规模问题上与穷举一致，`safe=true` 均通过独立复核，失败类别与证据边界清楚。跨工具需求适配、反馈重搜和最终方案判定由项目负责人统筹。
