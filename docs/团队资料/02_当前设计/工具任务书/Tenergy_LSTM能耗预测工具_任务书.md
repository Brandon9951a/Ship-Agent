# 组员任务书一：Tenergy——LSTM 推进功率与能耗预测工具

## 1. 任务定位

**目标**：为豫交投001的候选航速方案提供可重复调用的推进功率时序预测，并对有效时间区间积分，得到推进电机侧电耗。Tenergy 是 Tspeed 的目标函数评估器，也是 Tmanagement 所需功率需求曲线的上游。交付物是可训练、可离线评估、可在优化循环中批量推理的数值工具，不是让大语言模型估算电耗。

导师论文《内河船舶航速与能量管理协同优化方法与试验研究》PDF第73–75页以豫交投001的对地航速、加速度、水流速度、水深、风速、风向预测未来5个阶段的推进功率，再积分求电耗。其两层 LSTM（200、50节点）、400轮、批量64、MAE损失和Adam优化器是**复现实验起点**，论文报告的精度不是本项目成果。本任务使用本项目三份数据重新训练、划分、验证。

## 2. 数据与计量边界

| 来源 | 当前可用性 | 处理要求 |
|---|---|---|
| `data.xlsx` | 12,257个连续5秒点；航速、水流、水深、风速、风向、电机功率均有数值；加速度可由相邻航速计算。航速与正电机功率同时成立的点为7,037个，连续17点窗口为6,635个。 | 它是一份独立航行记录，窗口高度重叠。相对时间不能当日历时间；水流速度全为负值，方向定义未明，不擅自取绝对值。 |
| `log4p-10-29(1).csv` | 按唯一时间戳有6,324个速度—功率配对点。 | 有重复时间戳、缺速度；无水流速度列，风速单位码未确认。 |
| `log4p-10-31(1).csv` | 按唯一时间戳有11,340个速度—功率配对点。 | 同上。不能把同一时间戳的多行当作多次独立采样。 |

原始数据只读。CSV对地航速单位为节，`motor_power`单位为kW；内部航速统一换算为km/h，计算加速度时先换算为m/s并使用真实相邻时间差。`motor_power`先定义为**主推进电机功率观测量**，其具体电气测量边界仍待核实。训练标签、输出和验证报告必须写明“电机侧”；不得把它直接命名为电池侧总功率。负功率、停泊零功率、缺失、异常跳变分别标记并制定规则，不能统一填零。

## 3. 输入输出与共同接口

输入应分成三类：①预测时刻以前的有效历史观测；②候选方案给出的未来对地航速轨迹及可由它计算的加速度；③有来源的未来水深、水流、风等环境情景。未来真实电机功率不得作为推理输入。主模型先使用三份数据共同可核对的航速、加速度；水深经单位与质量核对后加入。论文六输入版本用Excel作为扩展实验，不能把缺水流的CSV伪填成完整六输入样本。历史窗口长度、预测步长和训练工况掩码在训练前记录；先复现实验的未来5个预测步，5秒可作为本数据的初始步长，但不把论文中的“阶段”未经核对地等同于5秒。

提供 `evaluate(speed_plan, environment_scenario, history, model_version)` 与批量版本。返回每个预测时步的时间、航段ID、候选航速、预测电机功率、质量/外推标记、输入情景与模型版本；按航段返回移动时长、等待时长、预测电机能量、峰值预测功率及积分覆盖率。时间差以秒计，积分使用 `E=Σ P_k·Δt_k/3600`，明确采用左端、右端或梯形规则并保持训练评价和优化一致。等待时功率与辅助负载另列，不凭空推断。现有 `EnergyResult` 缺少功率时序和测量边界，先提交兼容的接口升级方案，再与 Tspeed、Tmanagement 统一字段；若未取得电机到电池母线的转换依据，电池侧字段保持未知，不输出完整SOC可行性。

## 4. 构建步骤

1. **冻结数据集版本**：记录三源文件哈希、字段映射、单位、采样间隔和质量规则。CSV先按时间戳合并；对同组速度/功率冲突保留离散度标记，只在预先定义的稳定规则下取代表值，否则排除该时步。断点、长缺口和异常值不能跨越成训练窗口。
2. **构造监督样本**：先划分数据来源/连续时间块，再在各自块内建立历史窗口和未来目标；训练、验证、测试之间设置至少一个完整窗口长度的隔离带。区分航行与停泊工况，避免模型只靠大量零功率获得虚高分数。归一化器仅在训练集拟合，并随模型保存。
3. **实现主模型**：采用能接收未来计划航速的条件式LSTM或“历史编码器＋未来已知变量解码器”。先做共同字段主模型，再做Excel六输入扩展；报告两者训练集与适用范围，不能把扩展模型用于缺字段的CSV。模型超参数从论文设置起步，在本项目验证集上调节并记录早停规则。
4. **形成规划推理链**：支持多个候选方案批量推理；用预测功率积分。若规划时域长于训练预测时域，明确滚动预测方法，测试误差累积；不能仅凭5步预测误差推断全航程能量误差。对训练速度范围外、环境缺测或长时外推返回标记或拒绝。
5. **交付可复现工件**：训练脚本、清洗脚本、冻结的数据划分、模型权重、归一化器、版本清单、调用示例和指标报告。模型加载后同一输入应得到同一输出；训练随机种子和依赖版本留存。

## 5. 验证计划与验收

- **数据验证**：复核去重后时间单调、5秒窗口连续性、单位换算、负值及缺失掩码；抽查若干原始时刻到训练样本的追溯链。测试未来功率列移除后模型仍能推理，排除目标泄漏。
- **预测验证**：至少做按来源留出及连续时间块留出两种评价，注明可能存在的跨来源分布差异。报告航行工况MAE、RMSE、不同预测步长误差、各速度区间误差、峰值误差和按连续片段积分的kWh绝对误差；零或极低真实能量片段不用不稳定的百分比指标。
- **对照验证**：在完全相同的数据划分上比较持续功率、简单速度—功率回归/三次方基线和LSTM。保留所有结果；若LSTM在关键留出集上没有优于基线，就报告失败原因并暂不把它作为可信规划模型。
- **接口验证**：对同一方案多次调用结果一致；模型必需的环境输入缺失、越训练范围、无有效历史、等待时间未知时返回明确状态；时序积分与航段汇总一致，`kW×h=kWh`。批量推理的耗时须在代表性DE调用规模下实测。

**完成标准**：能够用冻结版本一键重训和复现报告，能够对给定候选航速输出带来源与适用范围的电机侧功率时序及电耗，并提供真实留出集误差。是否可作为正式优化器的主预测器，由留出集结果与基线比较决定，不预设准确率。

## 6. 协作交接

先与 Tspeed 负责人冻结候选航速轨迹格式、推理步长、批量调用与缓存键；与 Tmanagement 负责人冻结功率测量边界及电机侧到母线需求的转换位置。数据字典与检查依据见 `docs/数据/字段字典.md`、`docs/数据/D1_数据检查报告.md`；现行结构见 `schemas/types.py` 和 `docs/接口/五工具接口契约.md`。接口调整由三位负责人共用同一版本，不在各工具内各自私设转换系数。
