# 组员任务书二：Tspeed——差分进化航速优化工具

> 项目定位：在真实约束下搜索航速的数值工具，向主智能体返回候选和诊断，不自行生成自然语言正式方案。与 Tenergy、Tmanagement 的时序、功率口径、状态和反馈统一采用[联调接口 v2](../../../接口/五工具联调接口_v2.md)。现行 `schemas/types.py` 仍承接旧演示代码；固定候选表不能代替连续 DE 搜索。

## 1. 任务定位

**目标**：给定航段、到港时间和运行约束，搜索剩余航程的航速轨迹，使预测能耗尽可能低，并给出逐项可核验的可行性结论。Tspeed 的数值求解采用差分进化（DE）；Tenergy 为其候选方案提供功率与电耗；最终选定方案的功率时序交给 Tmanagement。DE 不作“全局最优”保证，也不替代约束检查器。

导师论文PDF第70–78页采用剩余航程能耗加相邻巡航航速差异惩罚作为目标，约束航速、加速度、特殊航段、时间与距离。其DE实验配置为种群50、最多500代、变异系数 `F=0.5`、交叉率 `CR=0.9`；豫交投001滚动周期为1800秒。这些是**复现实验起点**，最终配置要根据本项目LSTM推理耗时、解稳定性和重规划要求确定。

## 2. 决策变量、目标与约束

首版决策向量为当前剩余航程每个可优化航段的目标对地航速 `v_i`（内部km/h）；港口、船闸、限航区等特殊阶段按 Tseg 输出的上下限处理。跨段过渡需展开为满足加减速上限的速度轨迹，不能把速度瞬时跳变当成可执行方案。航段移动时间由距离与实际展开后的速度积分得到；等待时间单列计入总时长及辅助能耗。已走过航段不参与滚动重规划。

主目标为 `J = E_pred + λ·Σ(v_i-v_(i+1))²`。其中 `E_pred` 必须注明是电机侧推进能量还是经核实转换后的电池侧需求；惩罚项需先做量纲/尺度处理并通过敏感性实验选择 `λ`，导师取值10仅用于复现实验。若电池侧转换、辅助负载或有效容量未知，可以运行**电机侧航速优化实验**，但不能宣称已通过SOC安全约束或返回完整实船安全方案。现有请求若选择 `min_time`，须实现相应目标与能量约束，或明确返回“该目标未支持”，不能悄悄仍按最小能耗求解。

硬约束至少包括：每段有效速度范围、特殊航段限速、加减速度、各段及总距离一致、最晚到港时间、已确认的同边界功率上限，以及有依据时的电池预算和两组电池可供功率。最早到港、补能停靠、调度窗口只在任务确有规定时启用。所有约束附来源与单位；语言模型不能自行改动SOC下限、限速或功率边界。缺失关键约束须返回缺参，不靠任意默认值制造可行方案。

## 3. 输入输出与共同接口

输入为结构化请求、剩余航段、当前位置/当前速度/剩余时间、未来环境情景、有来源的约束、Tenergy 批量预测器及共同需求构建器。每个 DE 个体的速度向量先展开为带航段、阶段、相对起点和时长的连续轨迹，预测时使用该个体自己的未来位置与环境；不能使用与候选无关的历史功率表查值。按 v2 `EnergyBatchRequest` 提交种群，接收逐候选结果，计量边界为主推进电机侧；有依据的转换和辅助负载由同一个需求构建器形成母线侧需求，供 Tspeed 的电池预算检查与 FDP 共用。

输出按 v2 `SpeedOptimizationResult` 返回选定候选 ID、速度向量及展开轨迹、逐时电机功率与母线需求引用、各段/全程时间和能量、目标函数分项、时间/速度/加速度/距离/功率/电量逐项检查、随机种子、DE 参数、代数、预测次数和本次搜索耗时。每次搜索和模型调用有父子 call ID，保留迭代轨迹、可行个体比例、违反约束统计与最优诊断候选。FDP 的调用次数由主图联调记录关联，不放进 Tspeed 单次输出。`search_unresolved` 表示本次启发式搜索未找到方案，不能转写成“已证明无解”；域外预测、缺参数与工具故障分别返回对应状态。不可执行的诊断候选不得放入选定方案字段。

Tmanagement 若拒绝选定的逐时母线需求，接收 `ManagementFeedback` 中的失败时间、功率/SOC 状态、约束来源、候选和电池配置哈希及建议搜索动作。只对适用范围内可证明的限制建立新的硬约束；SOC 路径相关失败应记录为候选拒绝或有条件的搜索提示，下一候选仍须再次运行 FDP。重搜经主图动作检查，并受独立预算控制；FDP 尚未通过时 Tspeed 的阶段性 `candidate_found` 不等于完整方案安全。

## 4. 构建步骤

1. **建立独立目标函数和约束检查器**：先用可解析的假功率函数验证距离、时间、限速、加减速和能量积分，随后替换为Tenergy批量推理。预测器输入应包含同一候选的未来速度与环境情景，不用与候选无关的历史功率表查值代替。
2. **实现DE/rand/1/bin或明确记录的变体**：在合法速度边界初始化种群，完成差分变异、交叉和选择；保存随机种子。越界候选采用固定修复/拒绝规则；硬约束以可行优先排序或明确罚则处理，最终都要独立复核，不能仅凭罚值低认定安全。
3. **控制计算成本**：对相同候选和模型版本缓存预测；批量向Tenergy提交种群；在代表性17航段、完整时域上测量单次和滚动求解耗时。若5秒全时域推理过慢，经过能量误差评估后使用较粗规划网格，并对最终候选用高分辨率重算。
4. **处理滚动重规划**：首次规划和事件触发均以当前位置、真实当前速度、剩余航段、剩余时间与最新环境情景求解。先复现论文1800秒周期，再评估偏差触发与周期设置；已执行航段及已消耗电量不得回滚。
5. **形成诊断输出**：记录最优值随代数变化、可行个体比例、约束违反原因、模型外推次数、方案时序及重算结果。与Tmanagement约定“筛选—FDP复核—必要时重搜”的闭环，避免在每个DE个体上完整运行高成本FDP。
6. **冻结联调版本**：与两个工具负责人及主图集成者共同提供 v2 机器可读 schema 和成功、域外、无解未证、FDP 反馈四类样例；用显式迁移层承接旧 `OptimizationResult`，缺逐时功率和双电池状态时返回不支持，不反向推断。

## 5. 验证计划与验收

- **算法正确性**：在2–4个小航段和固定解析功率函数上，与穷举/确定性最优解比较；检验修复、交叉、随机种子复现及不可行分类。DE可以有搜索误差，必须报告误差而非宣称精确最优。
- **约束验证**：覆盖时间过紧、SOC不足、某段限速冲突、加速度不满足、功率超限、无可用环境预测、当前位于中途航段等场景。最终返回的每个“可行”解必须通过独立检查器，且时间、距离、能量汇总与展开轨迹一致。
- **求解质量**：同一情景至少记录多随机种子的目标值分布、可行率和耗时；与固定/规则航速、现有有限网格方案在同一数据、同一硬约束下比较。节能率仅在双方均可行且采用同一能量口径时计算。
- **模型耦合**：固定Tenergy模型版本及环境情景，比较批量预测与单独调用结果；对模型外推或预测不可靠区域进行标记或限制。不同步的电机/电池功率边界不得进入同一约束比较。
- **双电池反馈**：构造一个速度约束均通过但需求峰值超过两组可供功率的场景，以及一个因 SOC 演化而失败的场景；前者仅在有依据时形成硬限制，后者保持路径相关诊断。验证受限重搜的调用预算、候选版本、FDP 再检查及最终成功门槛，禁止把 `candidate_found` 直接展示为安全方案。
- **计算预算**：在代表性完整航程测量每代 LSTM 候选数、批量耗时、内存、最终高分辨率重算和 FDP 反馈轮次；与规则航速、有限候选基线在相同模型和约束下比较。若算力不足，粗网格必须有积分误差评估，正式候选仍高精度复核。
- **滚动实验**：模拟水流/风情景变化、实际SOC偏差或临时限速，确认剩余航程重算、已执行部分冻结、剩余时间更新、失败时不生成执行计划。

**完成标准**：DE 能从结构化航段和可调用 LSTM 生成可复现的选定航速时序；最终候选经过独立约束和 FDP 复核，失败时给出 v2 诊断与有效反馈；提交基线、多种子稳定性、完整耗时、调用事件和旧接口迁移记录。是否适合实时 1800 秒周期，由实测耗时和结果质量判断。

## 6. 协作交接

与 Tenergy 负责人按[联调接口 v2](../../../接口/五工具联调接口_v2.md)冻结候选轨迹、时间网格映射、批量调用、缓存与模型版本；与 Tmanagement 负责人冻结母线需求工件、两组电池约束回传、FDP 再检查和失败预算。**Tspeed 负责人交付独立的共同需求构建器**，读取 Tdata 提供的有来源转换参数；另两位负责人分别核对电机侧输入及母线侧输出。交付机器可读 schema、成功/失败 JSON、受控随机种子、约束检查器、DE 搜索记录与调用明细。转换只能有一个采用版本，不在 DE 目标函数中暗置电机到母线效率。算法定位见[方案稿](../项目论文方案稿.md)第四节。
