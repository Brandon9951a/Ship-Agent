# 组员任务书三：Tmanagement——前向动态规划双电池能量管理工具

> 项目定位：基于同一逐时母线需求，对两组可调度研究电池做供能规划；不连接实船控制器。与 Tenergy、Tspeed 的时序、功率边界、失败反馈和工件格式统一采用[联调接口 v2](../../../接口/五工具联调接口_v2.md)。现行 `schemas/types.py` 中的合并容量/SOC 不能作为本工具的两组状态输入。

## 1. 任务定位

**目标**：给定Tspeed选定航速所对应的功率需求曲线，规划两组电池在每一时步的启用模式和输出功率，使负荷得到满足、两组SOC不越界，并在约束内降低功率成本、切换次数和SOC差。两组电池在本项目中是**可调度的研究模型**，不按豫交投001现有供电角色固定分工；工具输出属于仿真规划，不能表述为实船已经执行的控制。

导师论文PDF第101–103页对豫交投001使用三种模式：单启1号、单启2号、双组共同输出；采用前向动态规划（FDP），代价由功率、模式切换、SOC均衡和低负荷双组运行四部分构成。论文式（5-26）至（5-30）的权重 `k_p=10^-4`、`k_s=10^3`、`k_soc=0.3`、`k_low=10^5` 及低负荷阈值0.65是**原论文实验配置**。任务应先复现其定义，再针对本项目容量、时间步长和功率尺度做敏感性分析，不把这些数字当作实船安全阈值。

## 2. 双电池模型与功率口径

输入必须逐组提供有效容量 `C_i(kWh)`、初始SOC、规划SOC下限、最大/最小可输出功率、母线输出到电池能量变化的效率或等效损耗函数、允许的模式转换及来源。SOC内部为0–1。需求功率应为同一母线边界上的推进需求加辅助负载，并标明是否已包括转换损耗；电机功率与辅助负载不能直接求和后冒充电池功率。若只完成电机侧LSTM，必须用有依据的转换模型，或以明示假设构建仿真情景；未知效率不默认为1，未知辅助功率不默认为0。

当前三份历史数据中的 `one_battery_capacity`、`two_battery_capacity` 没有确认SOC或百分比定义，电池电流符号及设备拓扑也未核实。它们**不作为本任务SOC轨迹的真实标签**。可先使用来自船舶资料的已确认参数或具名仿真假设构建两组电池，再把参数组、来源和假设与结果一起保存。不得把仿真SOC误差称为实测误差。

## 3. FDP方法和接口

规划时步 `k` 的状态至少为 `(SOC_1, SOC_2, 上一模式)`；动作是模式1、模式2、模式3。单启模式由对应电池承担需求；双启模式首版按导师论文的SOC比例分配功率，再检查两组功率上下限，不能靠越界分配满足负荷。若研究扩展为双启模式下的可选功率分配比例，必须单独标为**本项目扩展实验**，与论文三模式复现结果分开报告。零负荷时两组输出为零并保留上一有效模式，避免凭空增加切换次数。

状态转移以母线输出功率 `P_i`、时长 `Δt_h` 和效率 `η_i` 计算，例如常数放电效率情景下 `SOC_i(k+1)=SOC_i(k)-P_i·Δt_h/(η_i C_i)`；若输入已是电池侧功率，不能再除以效率。每一步硬性满足 `P_1+P_2=P_demand`（允许明确的数值容差）、单组功率限制、SOC上下限和模式转换规则。FDP逐时展开可行状态，在相同或可比较的离散SOC状态上只保留最低累计代价路径，并保存前驱指针以回溯整个最优轨迹。SOC网格大小、时间步长和状态剪枝规则必须公开，并测试离散误差与计算耗时。

代价采用论文四项结构：功率项、切换项、SOC差项、模式3低负荷惩罚项。复现版依论文式（5-26）至（5-30）实现，并逐项输出累计代价；权重与功率/SOC尺度变化后不得暗中沿用原值。另实现论文第101–102页的状态机对照：参考其高负荷阈值60%、SOC差40%和滞环逻辑，这些只作对照参数，不是本项目硬性安全限值。

输入按 v2 `BatteryManagementRequest` 接收 Tspeed 选定的 `selected_demand_ref`、逐时母线需求、两组电池参数、初始 SOC、上一有效模式、模式转移规则、FDP 网格、权重和规划约束。需求工件由单一共享适配器把 Tenergy 的主电机侧功率转换并加入一次辅助负载；Tmanagement 不再暗加辅助负载或再除一遍效率。需求边界、转换/损耗来源或任一组关键参数未知时返回 `needs_input`，除非运行显式标注的研究仿真情景。回放和仿真状态逐字段带来源；未确认含义的 Excel `capacity` 不当作实测 SOC。

输出按 v2 `BatteryManagementResult` 提供 `safe`、两组逐时功率与 SOC、模式及切换、四项成本、约束检查、时序工件引用、算法/网格版本和计算耗时；按航段与全程汇总末端 SOC、各组电量、模式次数和损耗。每个区间都能复算 `P_1+P_2=P_demand`、SOC 转移及单组上限，总汇总能从逐时工件复算。`safe=true` 仅表示在明确的来源、假设、离散粒度和独立检查下通过；它不代表实船执行或模型外条件下均安全。

失败时生成 v2 `ManagementFeedback`：选定候选及需求工件 ID、失败区间、需求和可供功率、两组当时 SOC、违反的具体约束及来源、离散网格/剪枝条件、诊断确定性和建议动作。若是有来源且对候选族成立的母线功率上限，可传给 Tspeed 作为硬约束；依赖原候选 SOC 演化的失败不得被简化为所有新候选通用的局部功率限制。FDP 在当前离散网格未找到路径时，要区分网格/算力未解决与有证据的不可行，不把它表述为实船全局无解。反馈前核验请求修订、情景及电池配置哈希，避免新旧电池状态混用。

## 4. 构建步骤

1. **冻结参数与场景**：先定义两组电池参数、母线边界、效率、辅助负载、初始SOC、下限和出处。至少提供“相同初始SOC”“不同初始SOC”“单组不足而双组足够”三类可解释情景。
2. **先做可核验的状态转移器**：给定单步需求、动作和参数，计算两组输出与下一SOC，返回可行/失败原因。用解析算例核对单位和能量守恒，再嵌入FDP。
3. **实现论文三模式FDP与状态机**：逐时展开、累计成本、状态剪枝、路径回溯；复现论文权重后做网格和权重敏感性实验。不能仅做贪心逐步选成本最低模式并称为FDP。
4. **接入Tspeed时序**：读取共同需求构建器输出的逐时母线需求，航行与等待阶段均参与；将推进、辅助和转换损耗分项留痕。首版三模式仅处理放电供能；补能试算须另做有来源的充电状态转移，未完成时明确返回不支持，不能把负需求直接当作充电。FDP 失败时返回触发时段、需求、两组状态与违反的约束，供 Tspeed 重搜或主智能体解释；仅在诊断方法能证实时给出数值缺口，不能编造“最小能量缺口”。
5. **形成审计工件**：交付程序、参数配置、算法伪代码/状态图、典型场景运行轨迹、每项代价明细、模型适用边界和复现实验命令。模型代码不得直接操作实船接触器或BMS。
6. **共同接口联调**：与 Tspeed 负责人冻结 `PowerDemandSeries`、上一模式、网格重采样、`ManagementFeedback` 和安全判定；提供模式轨迹、两组功率/SOC 工件与成功、过载、SOC 触底、网格未解决四类机器可读样例。旧合并 `ManagementPlan` 只供演示迁移，不反推两组实测状态。

## 5. 验证计划与验收

- **单步不变量**：每个可行时步检查母线功率平衡、SOC转移、容量与效率单位、功率限值、SOC限值；累计电池能量变化与逐时输出/损耗一致。不可行时不得输出 `safe=true`。
- **算法正确性**：在2–4时步、少量SOC状态的小例子中穷举三模式全路径，确认FDP返回同一最低代价路径；覆盖单启、双启、零负荷、模式切换、SOC触底和单组过载。对离散网格重复计算并报告结果变化。
- **对照实验**：在相同需求曲线、初始SOC、容量、效率和硬约束下比较状态机与FDP。报告终点SOC差、最大SOC差、两组功率波动、模式切换次数、成本四项及约束违例；若某策略不可行，单独报告，不以其违规结果计算“改进率”。
- **敏感性与算力**：改变初始SOC差、负荷峰值、效率、权重、时步和SOC网格，绘制可行率/代价/计算耗时变化。使用Tspeed代表性全航程需求测试内存和运行时间，并明确所选离散粒度。
- **证据边界**：历史 `capacity` 字段未确认前，只能验证算法内部一致性和仿真比较；取得电池通道协议及同步记录后，才另做实船SOC轨迹误差验证。
- **反馈有效性**：在同一功率时序下构造“瞬时需求超过已知两组总可供功率”与“前期调度导致后期 SOC 不足”两例，核验反馈的来源、时段、适用范围及 Tspeed 重搜后再次 FDP 检查。不得把后者当成对所有轨迹都成立的瞬时功率上限。
- **网格和时间对齐**：在不同规划网格、SOC 粒度与等待区间上重复求解，报告约束违例、能量守恒、结果变化和耗时。重规划从当前可信两组 SOC、速度时刻及上一模式开始，已执行能量不得被重新分配。

**完成标准**：三模式 FDP 在指定场景按 v2 接口生成可复算的两组逐时轨迹；小规模结果与穷举一致；所有 `safe=true` 都通过独立约束检查；失败反馈可被 Tspeed 正确消费或清楚标明不可转化为硬约束。提交状态机对照、参数/网格敏感性、全航程耗时、工件与调用记录。实验结果可以为负面结果，不得填写导师论文效果数值作为本项目结果。

## 6. 协作交接

与 Tenergy 负责人确认主电机侧功率预测的测量边界；与 Tspeed 负责人按[联调接口 v2](../../../接口/五工具联调接口_v2.md)冻结共同需求工件、时间网格映射、两组独立参数、反馈结构与再检查条件。交付机器可读 schema、合法/异常 JSON、成本分项和时序工件、小例子穷举证明及全程性能记录。三位负责人共用同一转换版本，不在 Tmanagement 内另设母线换算系数。方法定位见[方案稿](../项目论文方案稿.md)第四节，数据语义见[字段字典](../../../数据/字段字典.md)。
