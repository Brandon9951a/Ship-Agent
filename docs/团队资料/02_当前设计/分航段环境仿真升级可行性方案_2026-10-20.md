# 分航段环境仿真升级可行性方案

日期：2026-10-20。核对基线：远端 main，提交 5da2bc6。

## 1. 目标与结论

将目前统一静水、无风的默认环境升级为分航段的具名仿真环境，使水流、载况、船闸等待以及后续风和浅水修正真实参与航速搜索、航时计算、能耗计算及双电池 SOC 计算。

技术上可行。现有系统已具备路线、时间轴、预测器协议、DE 搜索、选定需求工件、FDP 和独立复核，可以在这些接口上扩展。第一阶段无需新增船端数据、外部天气 API、专业水动力软件或新增模型训练。

本方案交付的是可复现的环境敏感性仿真能力。仿真参数明确标注来源和假设；具体河段流速、风况、水深没有资料时，使用命名测试情景，不声称这些值是当地真实情况。

## 3. 实施范围

### 第一阶段：必须完成

1. 分航段、沿航线方向的水流。
2. 对地航速与对水航速区分。
3. 空载、半载、满载修正档案。
4. 船闸等待和低速进出阶段。
5. 环境一致的航时预检、功率约束、能量积分和双电池复核。
6. 正向、返程、子航线及不利情景验证。

### 第二阶段：第一阶段通过后增加

1. 分航段风况及具名风阻修正档案。
2. 浅水、狭窄航段的具名附加阻力档案。
3. 常规与不利情景对比，展示能耗、历时和 SOC 差值。

首轮每段环境在一次任务内固定，不实现随到达时间变化的天气、水流和排队。首轮也不计算横流操纵、二维航迹、避碰、动态吃水和波浪响应。预留字段，但不把尚未建模的内容显示为已考虑。

## 4. 环境与参数配置

新增 configs/environment_scenarios.json；现有 research_agent.json 引用默认环境和参数档案。

每个航段环境至少包含：

| 字段 | 含义及规则 |
| --- | --- |
| scenario_id、version | 情景身份与版本 |
| physical_segment_id | 正返程共用的物理航段身份 |
| canonical_direction | 该物理航段约定的正方向，不凭地名猜测上下游 |
| current_along_canonical_mps | 沿约定正方向为正的水流速度 |
| wind_profile_id | 第二阶段风况/风阻档案，首轮明确为未启用 |
| channel_profile_id | 航道修正档案及适用范围 |
| source_mode、source_ref、assumption | measured/replay/simulation、来源与假设 |

船闸等待单独按事件保存 lock_id、等待时长、触发边界和规则。正返程的进出顺序不同，应解析成不同事件顺序；不能简单把正向等待列表反转。

载况档案至少包含 load_state、load_factor、reference_load_state、version 和来源。若没有可靠吃水资料，首轮只使用载况标签及敏感性系数，不编造吃水。

可使用空载 0.90、半载 1.00、满载 1.10 作为软件敏感性测试档案的初值，所有数值明确标注 simulation；这组数值不代表该船实测规律。基准系数与载况修正应分别版本化，避免重复修正。

建议登记以下情景：

| 情景 | 用途 |
| --- | --- |
| calm_reference | 零流、基准载况、无额外等待，用于旧版结果回归 |
| segmented_current_demo | 不同物理航段使用不同非零流速，验证分段和返程 |
| adverse_current_demo | 指定航向遭遇较强逆流，验证功率及航时边界 |
| lock_delay_demo | 同一环境增加明确船闸等待，验证时间和辅助用电 |
| adverse_environment_demo | 第二阶段叠加风与航道修正 |

情景中的每一个流速和等待时长均在配置中列明，不在每次求解时临时生成。默认情景需要为全部登记航段提供映射；缺项给出具体字段，不静默使用零流。

## 5. 水流与航速计算

### 5.1 保持现有搜索变量，显式派生对水航速

第一阶段继续让 DE 搜索对地巡航速度 v_ground，保留现有距离积分与主表展示口径。每个区间按水流计算对水速度：

    u_along_kmh = 3.6 × current_along_route_mps
    v_water_kmh = v_ground_kmh - u_along_kmh

返程依据物理航段方向对沿航向水流取反；不能仅按名称猜测顺逆流，也不能把风阻、载况和等待时间一律取反。

距离按对地航速积分；基础功率按对水航速计算。现有初始速度、巡航速度和加减速轨迹字段均要声明其航速口径，禁止一部分路径解释为对地速度、另一部分解释为对水速度。

首轮仅支持正向推进、对地速度大于 0 的受控航行。候选要求 v_water 大于配置的最小受控航速，且不超过对水航速上限；不支持随流漂航、倒车或水流发电。强流导致候选不满足条件时明确拒绝，不通过绝对值或截断伪造可行性。

### 5.2 两类限速同时检查

分别保存：

- 对地运行限速：航道、靠泊、进出闸的情景限制。
- 对水航速范围：推进模型和船舶运行档案允许范围。
- 推进功率上限、母线功率上限和双电池可供功率。

环境变化后，最高可行对地速度必须同时满足上述约束。现有 fastest_s 预检需要更新，不能继续直接使用原 max_speed_kmh。

预检使用可证明的乐观航时下界，仅当该下界仍超过期限时，才能直接判定时间不足；存在加减速、阶段约束时保留其下界性质。不能用粗略搜索没找到的速度作为“物理最短航时”。

## 6. 功率、能量和 SOC

第一阶段的推进功率模型为：

    P_motor_kw = c × v_water_kmh³ × load_factor × channel_factor
    P_bus_kw = P_motor_kw / conversion_efficiency + P_aux_kw
    E_bus_kwh = Σ(P_bus_kw × interval_s / 3600)

第一阶段 channel_factor = 1，第二阶段使用具名档案。风修正加入后，在电机侧形成统一推进需求，再统一计算转换损耗，禁止在母线和电机侧重复计入。

等待阶段的对地航速为 0，不能套用巡航关系得出“克服整段水流”的立方功率。首轮按系泊等待模型处理：推进功率为配置的等待值，辅助负载持续计入；若不模拟动力定位，明确写入假设。

FDP 消费环境修正后的同一份母线需求工件。SOC 继续由每组电池分配功率、容量与放电效率计算，不在展示层加减百分数。电机功率、母线需求和电池输出的计量边界分别记录。

已有参数先冻结为参考档案，先验证环境接入效果。随后再单独用用户提供的约 90 kW 经济航行、200 kW 峰值及 130–150 km 续航经验做量级检查。上述经验对应的载况、速度口径和报警 SOC 尚不完整，因此不同时强行拟合全部指标，也不把 200 kW 误当成整个系统所有负载合计上限。

## 7. 风、浅水及狭窄航段的第二阶段处理

缺少船体迎风面积、阻力系数、航向、吃水及可靠水深时，先使用有版本的附加阻力档案进行敏感性仿真，不直接声称实现了 ITTC 风阻或浅水修正方法。

风况至少区分作用方向，首版顺风不自动获得未经验证的推进补贴。若以后取得迎风面积与风阻系数，再启用基于相对风的附加阻力计算；与静风基础阻力的计量边界保持一致，防止重复计入。

浅水/狭窄修正只用于能耗敏感性研究。真实水深、吃水或富余水深缺失时，不能据此输出通过性和安全净空结论；相关字段标为未知。

方法参考：ITTC《Preparation, Conduct and Analysis of Speed/Power Trials》，2024，分别处理风、波浪与浅水等修正：https://www.ittc.info/media/11972/75-04-01-011.pdf 。本项目首轮具名参数档案不等同于完成该指南的方法实现。

## 10. 网页展示与失败建议

保留原版功能布局。主表“推荐航速”明确标为对地航速，环境摘要可放入现有计算依据区域；详细的对水航速、流速、修正参数及版本放在现有可展开部分，不新增独立研究页面。

面向船员的解释应对应已核实原因，例如：

- 时间不足：指出瓶颈航段和当前情景下的航时下界，并给出延长期限的重算入口。
- 功率不足：指出逆流航段及超限功率，提供降低航速/放宽期限的试算入口。
- 电量不足：指出两组初态、预计需求及可用电量；建议先补电并录入新 SOC 后重算。
- 求解预算耗尽：说明本次未算完，不直接断言航次不可行。

任何调整建议在未重新运行完整工具链前，只称“可尝试调整”。需要给出“调整后可行”的结论时，应有相应的重新求解及独立复核记录。

## 11. 验收标准

| 场景 | 必须满足的结果 |
| --- | --- |
| 零流参考环境 | 使用相同参数档案时，与旧解析模型的时间、能耗和 SOC 在约定数值容差内一致 |
| 恒定对水航速、正返程对照 | 推进功率一致；顺逆流的对地航速和航时符合关系式；电量随航时变化 |
| 恒定对地航速、正返程对照 | 逆流要求更高对水速度，基础推进功率更高；不可超过模型与功率边界 |
| 多航段变流速 | 每段使用对应环境；距离、时间和能量积分闭合；子航线沿用同一物理段环境 |
| 强顺流/强逆流边界 | 正确拒绝漂航、倒车等未支持工况；无负航时、负推进功率或自动发电 |
| 船闸等待 | 新增等待只计一次；等待辅助能耗符合 P_aux × 等待时长，阶段时间顺序正确 |
| 不同载况固定轨迹 | 在测试档案 load_factor 递增时，推进能耗按预期递增；电池容量和用户 SOC 不被改写 |
| 风/航道修正固定轨迹 | 第二阶段附加修正按档案作用，零修正可退化为第一阶段模型 |
| 时间和功率边界 | 预检和完整评价同口径；粗略估计不能误报物理不可行 |
| 工件错配与篡改 | 环境版本、载况、需求或快照不一致时拒绝复用 |
| 重复执行 | 相同输入、情景、配置和种子能够复现；工具计算不受模型措辞变化影响 |
| 线上端到端 | 真实模型按依赖顺序调用专业工具，成功经 FDP 和独立复核；失败有具体原因及可操作调整 |

需要区分固定轨迹的物理单调性测试与优化结果比较：改变环境后，优化器可能换速度，因此不能机械要求所有优化结果都呈现相同的大小关系。

单位测试与独立计算用例采用明确数值容差；距离、时间、能量守恒检查采用绝对/相对容差结合，阈值随单位在测试中声明，不用前端四舍五入后的数字反推通过。

## 12. 实施顺序与交付

1. M1：环境协议与独立计算。实现方向、单位、航速变换和阶段处理，用小规模手算用例验证。
2. M2：第一阶段五工具联调。接入水流、载况、等待；关闭速度扰动；更新预检、缓存和工件核验。
3. M3：网站联合验收。覆盖正返程、多航段、强逆流、等待、低 SOC 和紧时限；保留真实模型与工具证据。
4. M4：第二阶段环境修正。接入风和航道档案，新增对照及敏感性报告。

每阶段交付配置文件、实现代码、测试命令、通过/失败证据和限制说明。第一阶段先完成联合验收，再决定是否发布；第二阶段独立验收。

## 13. 2026-10-21 实施与验收状态

M1、M2、M4 已完成代码实现：集中环境配置、正返程流向、对地/对水速度、载况与风/航道系数、船闸等待、环境哈希绑定及独立功率重放。关闭原有随机速度扰动。LSTM 继续使用原短时接口。

M3 已完成本机真实浏览器十种航次测试：8 项通过 DE/FDP 与独立复核，2 项因最低 SOC 和过紧期限正确拒绝。另有五项真实 API 环境验收。网页发现的任务类型误判、港口/船闸被改写问题已修复并重测。

代码位于环境仿真集成分支，本轮验收环境为本机网站。Render 与 main 尚未发布本轮改动。完整输入、任务标识、数值、修复和复现方法见 [验收报告](../../验收/分航段环境与十次网页验收_2026-10-21/验收报告.md)。
