# 项目论文方案稿：基于 LangGraph 的数值可信航行智能体

## 一、LangGraph 概述

LangGraph 是一个面向智能体（Agent）编排的低层框架与运行时，由 LangChain 团队开发，其设计思想来源于谷歌的 Pregel 大规模图计算模型以及 Apache Beam。它的定位是解决长时间运行、有状态、可持久化的智能体系统的编排问题，而不是提供现成的提示词或业务抽象。与常见的一次性问答型大模型应用不同，LangGraph 将智能体的执行过程建模为一张有向图，用状态、节点、边三个基本元素描述整个运行过程。

在 LangGraph 中，状态（State）是一份贯穿全程的共享数据，记录智能体在工作过程中积累的所有信息，所有节点都可以读取并更新它。节点（Node）是完成具体工作的函数，既可以是调用大模型的语义处理步骤，也可以是纯代码的确定性计算步骤。边（Edge）负责路由，决定当前节点完成后下一步前往哪个节点，既可以是固定跳转，也可以是依赖当前状态的条件分支。

LangGraph 的执行引擎采用批量同步并行模型。每一次迭代被称为一个超步，超步内部又分为规划、执行、更新三个阶段。规划阶段确定本轮要执行哪些节点，执行阶段并行运行所有被选中的节点，更新阶段把节点写出的结果合并回状态。由于一个节点存在多条出边时，所有目标节点会在同一个超步内并行执行，LangGraph 天然支持任务并行。此外，LangGraph 提供了检查点（Checkpoint）机制，能够在每个超步边界保存状态快照，从而支持对话延续、暂停恢复、时间回溯以及人机协同等能力。人机协同通过中断函数实现，它允许智能体在任意位置暂停执行、保存现场并等待人工输入后再继续。

LangGraph 对智能体编排最有价值的一点，是它允许在同一张图里混用确定性的手工代码步骤与大模型驱动的智能步骤，使开发者可以精确控制大模型在哪些环节介入、哪些环节保持可预测和可审计。

## 二、本项目对 LangGraph 的适配设计

本项目构建的是一个面向内河纯电动船舶的航速优化与能量管理智能体，核心诉求是数值可信，也就是每一个工程数值都必须能够追溯到确定性计算，而不是由大模型直接生成。这一诉求与 LangGraph 的能力高度契合，因此本项目选择 LangGraph 作为编排底座，把整个智能体设计成一张图，利用状态、节点、条件边、检查点以及中断机制承载全部业务逻辑。

### 状态设计

本项目的状态包含以下若干关键字段。对话历史字段保存大模型与船员的全部交流，用于维护上下文。任务解析字段保存从船员口语中抽取的结构化航行请求，以及是否需要追问和追问内容。船舶状态字段保存补全后的船舶、电池与环境信息。航段与能耗字段依次保存航段划分结果、能耗预测结果、航速优化结果和能量管理方案，最终汇总为一份完整航行方案。此外，状态中还包含可行性标志、不可行原因、反思重规划轮次、航行进行状态、数值锁定是否通过、最终报告以及可追溯的执行轨迹。这些字段共同构成智能体在图执行过程中唯一的数据契约，节点之间只通过状态传递信息。

### 三层架构与决策权边界

本项目将智能体的职责划分为决策层、计算层和安全层三个层次，并逐一映射到 LangGraph 的节点与边。决策层由大模型承担，只负责语义解析、妥协选项呈现和报告解释三件事。计算层由确定性工具承担，完成全部数值计算。安全层由规则承担，负责数值锁定与可行性校验。

与这一分层相对应的是一条严格的决策权边界。大模型在整个图中只有三处自主决策权，分别是把船员口语解析为结构化请求、在方案不可行时向船员呈现妥协选项并解释推荐理由、以及把最终方案润色为船员能理解的语言。除此之外的环节全部由工具和规则锁死。数据补全、航段划分、能耗计算、航速求解和能量分配由工具完成，可行性判断、阈值比较和轮次上限等客观可判定的分支由规则完成，只有补能还是降速这类存在取舍权衡的选择才交给船员确认。这一设计从根上杜绝了大模型越权编造数值的可能。

## 三、工作流设计

本项目的工作流由三条主链路和七条条件边组成，全部由 LangGraph 的状态机驱动。

### 航前基线规划主流程

主流程从任务解析节点开始，大模型将船员口语转换为结构化的航行请求。随后一条规则条件边检查关键字段是否齐全，若缺少起终点、电量、时间等关键信息，则转入追问节点向船员索取补充，等待用户输入后重新解析。字段齐全时进入数据获取节点，补全船舶、电池与环境状态，这一过程遵循用户输入优先、缺失项从历史分布或配置默认补全的原则。之后进入航段划分节点，将整个航程切分为若干约束同质的子航段。航段划分完成后依次进入能耗预测节点和航速优化节点，前者计算各候选航速下的能耗、电量和到达电量，后者在时间、电量、限速、船闸等约束下求解推荐航速并给出可行性结论。

航速优化节点之后是一条关键的可行性条件边，它直接读取求解器输出的可行性布尔值，而不是交给大模型判断。若方案可行，则继续进入能量管理节点，用动态规划方法规划两组电池的供能模式，随后由大模型生成报告，最后经过数值锁定节点校验后结束。若方案不可行，则进入反思循环，由意图翻译器枚举妥协选项、大模型文案化、中断函数询问船员，船员选定方向后再翻译成输入修改并重新求解。

### 航中滚动重规划

智能体在航行过程中并非一次求解后就固定不变。环境仿真器持续输出当前环境、实际电量和临时限航通告，一条规则条件边据此判断是否出现偏差超阈值或硬性事件。若未触发，则继续按原方案推进；若触发，则首先锁定已经走过的航段，以当前位置和当前真实状态为新起点，只对剩余航程重新执行航段划分、能耗预测、航速优化和能量管理，最后生成报告解释方案变化的原因，并同样经过数值锁定校验。这一机制使智能体具备对环境变化的动态适应能力。

### 补能迭代闭环

航段划分内部存在一个迭代闭环。补能点是否停靠依赖于电量规划，而电量规划又依赖于航段划分，二者相互耦合。因此设计上采用迭代解耦的方式，初始分段不包含补能点，先用能耗预测和航速优化计算全程电量轨迹，再判断途中电量是否跌破报警阈值。若未跌破，分段确定；若跌破，则在跌破点上游最近的补能点插入补能断点并重新分段，最多迭代三轮，超过轮次则判定不可行并转入反思循环。

### 反思循环与条件边路由

反思循环是本项目处理不可行场景的核心机制。当航速优化节点输出不可行结论时，它同时携带一个结构化的不可行类型。意图翻译器根据该类型查表，枚举出相关的两到三个妥协方向，并对每个方向试算一次以得到带具体数值的选项，例如晚到十五分钟、到达电量降至百分之二十、提前三十分钟出发、在漯河港补电三十五分钟、全程降速到八点一节或放弃。随后中断函数暂停执行，把这些选项抛给船员，由船员选择能接受的方向。船员选定后，意图翻译器把选择翻译成优化问题的输入修改，例如放宽到港时间、下调电量下限、调整出发时间、插入补能断点或将时间约束软化为省电优先，然后工具在修改后的输入上重新求解。若仍不可行，则在船员所选方向上做增量搜索，逐步加大妥协幅度，最多两轮。整个过程中，船员只负责选方向，数值始终由工具试算得出，大模型只负责把选项和推荐理由用船员能理解的语言呈现出来。

七条条件边中，有六条由规则判定，分别是关键字段是否缺失、方案是否可行、反思轮次是否超限、途中电量是否跌破阈值、补能迭代是否超限、环境是否触发重规划；仅有一条，即补能还是降速的选择，交给船员确认。这样设计的原则是，凡是客观可判定的分支全部用规则锁死，凡是有取舍权衡的分支才交由人工拍板，大模型不参与路由判断。

## 四、工具系统设计

本项目的计算层由五个确定性工具组成，它们全部以结构化数据为输入输出，杜绝自由文本传值。

数据获取工具负责补全船舶、电池与环境状态，遵循用户输入优先、缺失项从历史分布或配置默认补全的规则，并为每一项数据标注来源，同时对异常值做检测，当用户输入与事实表冲突时返回冲突提示而非静默修正。

航段划分工具负责把航程切分为约束同质的子航段。它采用候选断点加激活条件的设计，断点分为八类，船闸为硬断点必切，港口码头只有在有停靠任务时才切，补能点只有在电量规划需要补能时才切，限速区、桥区和管制区必切，水深受限区在水深逼近吃水时才切，气象和水文突变点按阈值触发，时间锚点按任务要求切分。该工具支持传入任意起点，以便航中重规划时从当前位置只切剩余航程。

能耗预测工具采用物理三次方与残差学习模型作为基线，为每个候选航速输出功率、电耗、时间和到达电量以及风险标识，后续可扩展长短期记忆网络和随机森林作为增强，三类模型统一接口。

航速优化工具在时间、电量、限速、船闸和通航管制等约束下求解推荐航速序列。其约束参数设计为可外部传入和修改，时间约束可以在软硬之间切换，电量下限可调，出发时间可改，这正是支撑反思循环中各项妥协意图的前提。该工具有一条硬规则，即不可行时必须返回结构化的不可行类型和原因，禁止编造假方案。

能量管理工具根据航速优化产生的功率需求，用前向动态规划方法规划两组电池的供能模式，动作空间包括单独启动一号电池、单独启动二号电池和双电池组同时输出三种，代价函数综合考虑功率成本、切换成本、电量均衡成本和低负荷双电池惩罚，输出每段两组电池的功率、段末电量和供能模式。

在五个工具之外，系统还设计了两个支撑组件。意图翻译器是一个独立的确定性组件，负责枚举妥协选项并把船员的选择翻译成优化问题的输入修改，其核心是两张规则化映射表，一张描述不可行类型到候选意图的对应关系，另一张描述意图到输入修改和重算工具的对应关系，运行时大模型不参与相关性的判断，只负责把选项文案化。数值锁定组件是一个独立的校验节点，负责抽取报告中的数字并与方案字段逐一比对，发现偏离时带纠错提示重试一次，重试后仍偏离则回退到只引用方案字段的模板报告，从机制上保证最终输出中的每一个数字都可追溯。

## 五、总结

本项目以 LangGraph 为编排底座，通过状态、节点和条件边的组合，将大模型的语义决策能力与确定性工具的数值计算能力严格分离，并用规则和人工确认兜底边界。整条技术路线的核心可以概括为，语义交给大模型，计算交给工具，边界用规则兜底，让大模型做选择题而不做填空题。这一设计使智能体在保持自然语言交互灵活性的同时，保证了每一个工程数值的可信、可追溯与可验证。
