## 修复内容

1. 原网页仍发送 `scenario_id=route_success, task_type=auto`。解析器可提取 `prediction_backend`、`prediction_duration_s` 和显式 `trajectory`；默认解析情景可直接调用 Tenergy，不再返回 `select_lstm_scenario`。
2. 解析预测实际调用 `AnalyticPowerPredictor.predict()`，使用配置中的 `P_motor=0.055*v³`。有显式轨迹时校验阶段、速度、连续时间轴和资源上限；有时长与用户航速时生成定速轨迹；否则在 Tenergy 内解析已登记连续航段，采用具名情景航速展开轨迹并核对距离。默认航速不是 DE 优化结果。
3. 逐区间功率、能量积分、时间范围、单位、模型版本、环境及数据来源均保存为 SHA256 工件。母线需求仅由现有共享需求构建器转换一次。缺转换依据时保留电机侧预测，母线值为 null 并保存诊断。
4. 显式 LSTM 可从普通网页的默认情景进入，继续加载真实冻结权重和历史样本。20 秒具名样本可计算并完成原有 Tspeed 评价交接；40 秒为 8 步，超过 5 步窗口，返回 `model_out_of_domain`。显式逐区间 LSTM 轨迹也可调用；无解析后端回退。
5. 修复 LSTM 能量导出的浮点精度问题：先把模型输出转为 Python float，再计算 `P*dt/3600`，与已导出功率及联调层严格积分保持一致；不改权重、训练或批准状态。
6. 预测完成前读取并校验关联工件，复算逐区间及总能量、时间连续性和母线积分，保存 `prediction_verified` 事件。缺预测信息时可在同一 task 补参并升版重算；模型不能跳过 Tenergy 直接完成。
7. 网页单独展示“能耗预测完成”、后端、来源、工件及诊断，清除到港 SOC/ETA，不生成航次方案或播放航行回放。域外拒绝不会被展示为航次不可行。

### 真实调用发现并修复的答复问题

首次 LSTM 20 秒实测任务 `3809fa6e-e10b-43fd-9d03-6e8679f9fe8a` 的工具计算成功，但模型正文复制了版本号，触发数值校验。第二次任务 `fb481544-432a-4c3d-a272-b72454f35d1b` 又复制了无关电池参数，仍被拦截并显示工具兜底答复。没有将这些答复标为通过。

最终将独立预测答复上下文收敛到已复核预测指标、后端、轨迹/历史来源和诊断代码；完整 Tdata/模型版本保留在证据面板。补充版本号/字段编号的提示，不放宽原有数值校验。验收脚本同时收紧为模型正文必须 `accepted`，并核验后端、调用顺序、缺失字段和同任务升版；修复后的完整实测共 5 项全部通过。新增回归保证预测工件损坏时最终答复保留 `verification_failed`。

尚未进行浏览器人工外观验收；本轮通过真实网站 API 链路和前端投影/渲染执行测试。

## 仍存在的限制

- 解析后端是具名软件仿真计算器，环境修正和实船载况尚未标定，不代表实船能耗精度、节能率或运营批准。
- 默认航段预测需要已登记的连续起终点；没有航段或显式轨迹时询问输入，不推测目的地。该 PR 不扩展航线覆盖。
- LSTM 无用户显式轨迹时使用项目具名 10 km/h 短样本和冻结历史；不是现场观测历史。5 步窗口及原有特征域保持不变，不能把短时结果推广到全航程。
- LSTM `planner_approved=false`，正式规划仍不批准；未知等待/环境、母线转换缺失的规则不因本次修复改变。自定义 LSTM 轨迹仅做短轨迹预测，不声称已经 DE/FDP 全链规划。
- 独立预测成功只返回 `prediction_completed`。双电池 SOC、航次可行性和全局最优性均不由该状态推出。
