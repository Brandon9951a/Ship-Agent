## 联合修复

- 规划任务的专业调用顺序由运行时确定：`Tdata → Tseg → Tspeed → Tmanagement → prepare_final`。模型仍真实请求每步动作，但不能在求解前绕到无关辅助工具而耗尽预算。
- 模型解析返回非法 JSON 时，记录拒绝事件并提供一次修正机会，避免工具尚未启动即报泛化 `tool_error`。
- 独立预测完成后直接进入复核与答复，避免无关结果查询误用任务 ID。
- 航段最短可能历时大于期限时，Tspeed 直接给出距离、最快历时、期限来源和可修改字段；不能把此类明确时限冲突说成求解器不确定。
- FDP 在第二次搜索中改变 SOC 网格后，管理工件同时保存原请求和实际求解请求；独立复核以实际求解网格重放。
- 失败答复的模型正文若未通过数值核验，确定的期限诊断仍由代码展示，包含最短历时、用户期限和“延长时限或缩短航段”的待重算建议。

## 验收限制

- 目前 72 组合清单以**默认 1 小时**为条件；长航段多数属于可证明的期限冲突。需按用户输入的实际时限重新求解，不能把清单中的失败读成航线永久不可行。
- LSTM 仅覆盖短时轨迹。长航程仍使用解析功率仿真；本轮不涉及实船标定、途中充电或全局最优证明。
- FDP 的粗网格重试保留原始网格、重试网格、预算及复核记录。若两轮均耗尽预算，应报告 `solver_unresolved`，不得称为不可行。
- 本轮没有并入 `main`。请从审查分支验收，确认后再决定并入。
