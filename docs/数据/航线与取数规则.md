# 航线与取数规则

## D1 状态

本文是 C 负责的航线事实与 Tdata/Tseg 规则基线。距离来自项目 D1 任务表中的资料值，尚未完成逐项人工核源；因此不能将本文件当作实船测量或可行性证明。

## 航线事实

正向路线为：平顶山港 -> 军李船闸 -> 马湾船闸 -> 漯河船闸 -> 漯河港 -> 大路李船闸 -> 葫芦湾船闸 -> 周口船闸 -> 周口港。

八段距离合计 189.789 km。配置中保留漯河船闸和漯河港两个独立节点，不合并港口与船闸。

反向路线必须按实际起终点反转段顺序，不能只替换正向路线的起点和终点。中间起终点使用连续的子序列；不连续或无法识别的地点必须追问。

## Tdata 规则

Tdata 应输出契约中的 `DataContext`。用户在 `VoyageRequest` 中明确提供的值优先；配置只能补全允许的缺失事实，并为每个采用值记录 `SourceRef`。来源未确认、字段冲突或关键参数缺失时，保留 `conflicts`、`missing_fields` 和 `assumptions`，返回 `need_clarification`，不得填入工程数值。

本 D1 配置未提供限速、最低速度、闸等待、充电功率、充电可用性或充电等待，因此这些字段保持未知。未知等待时间不能写成 0；未知充电能力不能承诺补能可行。

用户输入与事实配置冲突时，应保留冲突候选并说明 resolution 尚未确定。用户不能覆盖硬安全限制；参数采用和冲突处理由 A 确认。

## Tseg 规则

Tseg 应输出 `ToolResponse.payload = {"segments": [...]}`，每段字段遵循 `Segment`：`segment_id`、`origin`、`destination`、`distance_km`、`max_speed_kmh`、`min_speed_kmh`、`waiting_h`、`source`、`assumptions`。

内部单位固定为 km、km/h 和 h。无法确认限速或等待时，Tseg 不应生成可计算的完整成功结果；应返回缺失字段和追问。正向、反向和子航线的返回顺序必须与实际路线顺序一致。

## 充电事实

当前资料未确认充电地点、功率、可用性或等待时间。相关字段保持缺失状态。后续只有取得真实来源或 A 批准的明确演示假设后，才能加入配置，并必须标明 `kind: document`、`measurement` 或 `assumption`。
