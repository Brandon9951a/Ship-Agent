## 配置与审计程序

`configs/vessel_facts.yaml`保存候选、单位、位置、含义、用途、提案、确认状态和确认人；`configs/limits.yaml`单独保存SOC阈值与功率/容量/拓扑/能耗口径。文件采用JSON语法的YAML 1.2子集，由Python标准库`json`读取，暂不增加A维护的公共依赖。

运行：

```powershell
.\.venv\Scripts\python.exe -m tools.vessel_facts
```

当前应返回`need_clarification`、空`adopted`和退出码2，代表事实采用不完整。退出码1代表非法配置，0代表所需采用记录和边界已齐备，不是实船性能证明。

A确定采用参数后，对相应记录填写以下结构，数值和来源按实际批准内容填入：

```json
{"adopted": {"value": 100, "source": {"source_id": "approved-demo-only", "kind": "assumption", "locator": "A批准记录位置", "confirmed": false, "note": "仅示范结构的测试值，禁止直接用于实船"}}, "confirmed_by": "A的实际确认记录", "confirmation_status": "approved_A"}
```

文档来源采用时`confirmed`必须为true并带位置；演示假设必须有说明和确认记录。审计不自动批准提案或把候选填入`VesselState`。C的Tdata可以读取这些事实，但必须使用A的业务结构、保留来源和未解决项。

本次复核：历史三表现已到位，首轮体检完成；原调研报告仍缺。capacity/SOC字段和电池侧计量边界不因数据存在而自动批准。SOC限制记录补齐用途、提案、候选和确认状态，与船舶参数使用同一候选审计规则；候选25%/20%保持0.25/0.20且不隐式采用。审计的`calculation_ready`只检查最低能量预算输入，不保证完整VesselState，也不代表实船安全批准。
