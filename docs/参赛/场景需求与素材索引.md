# 场景需求与素材索引

## D1 状态

本文整理 C 负责的需求分析素材和演示场景。当前内容来自仓库已有项目资料和接口约束，不虚构访谈、部署记录或用户验证。需要原始调研材料支撑的条目标为“待核实”。

## 场景与需求矩阵

| 场景 | 用户任务 | 系统应提供 | 当前依据 | 状态 |
|---|---|---|---|---|
| 正常可行 | 输入起终点、时间、SOC、载况/吃水，获取航行计划 | 航段、航速、耗时/ETA、能耗、SOC 和来源 | `docs/团队资料/00_必读/D1_2026-09-18_任务与验收.md` C2；五工具契约 | 待 B 计算结果 |
| 时间不可行 | 到达约束过紧时了解原因并选择调整方向 | `infeasible`、time 分类、试算选项和重算状态 | D1 C2；`schemas/types.py` 状态定义 | 待 A/B 流程 |
| SOC 不足 | 避免输出电量不安全的方案 | `infeasible`、soc 分类、依据明确的补能/任务调整建议 | D1 C2；接口契约 ManagementPlan 规则 | 待 B 能量预算 |
| 缺少参数 | 不完整输入时知道需要补什么 | `need_clarification`、`missing_fields`、`questions` | `schemas/validate.py`；Tdata 规则 | 待 Tdata 实现 |
| 子航线/返程 | 选择中间节点或返程时保持路线正确 | 连续段顺序、逐段距离、来源和未知限制 | `docs/数据/子航线与返程手工核对.md` | 已完成 D1 设计 |
| 工具/模型失败 | 服务故障时避免误导性成功结果 | `failed`、原因、回退状态和追踪日志 | 五工具接口契约状态表 | 待主流程接入 |

## 用户与痛点素材

| 素材主题 | 可用于方案正文的要点 | 来源 | 状态 |
|---|---|---|---|
| 航线复杂 | 八段航线包含港口、船闸和方向变化，不能把港口与船闸合并 | D1 C1、route facts 配置 | 已整理，原始页码待补 |
| 约束不完整 | 限速、闸等待和充电能力可能缺失，系统应显式追问而不是猜测 | 五工具接口契约；D1 C1 | 已有规则依据 |
| 决策可解释 | 结果需要显示来源、单位、假设、约束和失败原因 | 五工具接口契约；本周实现范围 | 已有规则依据 |
| 安全边界 | SOC 不足、时间不可行时应拒绝不安全方案并给出可审计原因 | D1 C2；七日任务表 | 待 B/A 具体结果 |
| 用户调节 | 不可行时由用户选择调整方向，不能由系统偷偷放宽安全下限 | D1 C2；技术方案汇总 | 待 A 流程实现 |

- 可以表述：系统设计为在资料缺失时追问，并保留来源和冲突。
- 可以表述：D1 已完成航线事实配置、场景定义和演示草图。
