### 第1章 项目概述

1.1 背景与意义：说明纯电动船舶航行中能量储备、时效、航段条件和操作复杂度的关系。引用船舶调研资料的具体位置，不把研究对象的资料直接推断为全行业统计。

1.2 目标定位：明确服务对象、典型任务、输入与输出，定位为辅助决策原型。安全约束优先于时效和能耗目标，不代替船员、调度或法定航行要求。

1.3 创新点：围绕自然语言任务与可核查计算的连接、硬约束校验、不可行解释及用户选择后重新计算，说明与人工配置或单次计算的差异。每个创新点注明设计、实现、验证状态。

交付要求：A 提供目标与创新点表；C 提供场景图及使用流程。不得只列框架名称作为创新依据。

### 第2章 需求分析

2.1 问题剖析：描述任务下达、参数获取、方案计算、异常处理、结果确认的实际工作流程及痛点。

2.2 用户需求分析：有问卷或访谈则提供真实时间、样本数量、问题及结论；暂未开展时采用可追溯的资料分析或案例分析，不能编造调研人数或满意度。

2.3 场景与需求矩阵，至少覆盖：

| 需求 | 输入或触发条件 | 预期行为 | 验证方法 |
|---|---|---|---|
| 正常航行规划 | 航线、初始SOC、任务时间等齐全 | 返回有工具依据的建议与轨迹 | 标准案例复算 |
| 缺参追问 | 关键字段缺失或冲突 | 说明缺项，不自行猜测 | 缺参测试 |
| 时间不可行 | 要求超过可行速度或时间边界 | 明确原因，提供试算后的调整选项 | 边界案例 |
| 能量不可行 | SOC或功率约束不满足 | 返回不可行或补能建议，不伪造方案 | 能量边界案例 |
| 用户调整 | 用户选择调整时间或能量条件 | 更新状态并重新调用受影响工具 | 多轮案例 |
| 模型服务故障 | 超时、错误或不合法响应 | 明确故障，按已实现策略回退 | 故障测试 |

交付要求：C 提供「需求—功能—用例—证据文件」对应表，标明资料来源和未验证的需求假设；B 复核涉及工程约束的部分。

### 第3章 解决方案设计

3.1 技术路线：自然语言任务 → 结构化请求 → 数据与航段 → 能耗预测 → 约束下航速优化 → 能量管理 → 校验与解释。补充缺参、不可行、人工选择、服务故障分支。

3.2 系统架构：绘制用户界面、LangGraph 状态与节点、模型调用层、五工具、数据配置、校验及日志的关系图。未实现节点在内部草图标为计划项，定稿以冻结版本为准。

3.3 功能模块：按[五工具接口契约](../接口/五工具接口契约.md)及 schemas 描述 Tdata、Tseg、Tenergy、Tspeed、Tmanagement 的输入、输出、错误和责任边界。

3.4 模型与计算职责：DeepSeek 官方 API 的非思考模式负责语义理解和解释；工程数值由 Python 计算工具生成并校验。应用无需以本地部署或微调大语言模型作为本周前置条件。航行数据拟合能耗模型与大语言模型微调是不同工作，须分别准确描述。

3.5 方法与假设：B 提供能耗模型、拟合或参数来源、求解目标、约束、单位、SOC更新方式和等待能耗处理；不能将候选方法写成已采用方法。A 决定存在冲突的采用值和安全边界。

3.6 可行性与安全：列出算力、网络、API额度、开发资源及成本依据；说明数据使用权限、隐私保护、模型幻觉控制及航行安全边界。没有实测成本时只提供测算方法和待测项。

交付要求：A 两张图和模块表；B 方法与参数表；C 航线与界面设计。图、文字、接口名称必须一致。

4.2 技术实现：列出已实现的节点、计算工具、配置和调用方式；提供版本号或提交哈希。说明本地应用、联网模型服务、密钥环境变量及无密钥示例配置。

4.3 数据处理：B 交付数据字典、单位校验、异常和缺失处理、训练/验证划分方法；C 交付航线、距离及来源核验。模型拟合与评估应避免相邻数据泄漏，具体方法须与实现一致。

4.4 团队协作：A 架构、接口、决策、审核、统稿及提交；B 数值计算、参数核验、算法及测试；C 场景与航线、界面、素材和演示。匿名稿使用角色描述，不加入学校或教师身份。

### 第5章 测试与验证

5.1 测试方案：注明冻结提交、运行环境、依赖版本、数据来源、输入、预期结果、实际结果和判定标准。

5.2 功能与边界测试：正常、缺参、非法输入、时间不可行、能量不可行、局部航线、反向航行、多轮调整，以及调整后受影响结果重新计算。

5.3 数值验证：检查距离/时间/能耗/SOC/功率的单位和一致性；用手算或独立参考计算复核代表案例；报告拟合误差和适用范围，不外推到未覆盖的工况。

5.4 性能与可靠性：分别记录工具耗时、模型调用耗时和端到端耗时；检查超时、断网、错误响应及已实现回退。A3 最小连接测试不能作为完整业务响应时间。

5.5 对比实验：只有在同任务、同约束、同模型及同数据口径下，与明确的基准策略比较。说明基准、样本量、公式和原始结果。没有有效对比时不填节能率。

5.6 结果与问题：既列通过项，也列失败项、未测项、已修复项和剩余限制；不能只展示成功截图。

交付要求：B 提供可复现实验脚本、测试报告、案例输入输出和结果表；A 复核运行与口径；C 录制同版本演示并整理图表。
