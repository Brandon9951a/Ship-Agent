## 复审发现与修正

- 成功工具信封仅检查 payload 存在：改为按五工具名称解码与校验业务记录，拒绝空/错误结构。
- 追问、失败、不可行方案被要求完整数据：改为区分诊断记录和最终成功计划。
- 不可行/不安全 payload 可被包装为 ok：现在拒绝状态与内容矛盾。
- 未知补能/辅助能耗可能被解释为安全：安全方案必须明确这些字段。
- 预算可能超过扣除安全储备后的电量：增加容量/SOC 预算上界校验。
- SOC 总变化及中间轨迹可能与能耗不一致：增加总量、单调性和分段对应检查。
- 极大数值输入可能触发溢出：现在返回非法输入。
- 文档仍要求等待 B/C 接口审批：改为 A 已指定的统一开发基线。

此次保留业务字段名称与现有入口，没有新增运行依赖，没有选定未经确认的实船参数。
