## 2. 已对齐的研究系统方案

### 五个工具与数值链路

| 工具 | 已选方法与职责 | 当前边界 |
| --- | --- | --- |
| `Tdata` | 获取并核验船舶、双电池、环境及任务事实，附来源和质量标记 | 关键实船参数无来源时保留未知；仿真假设须具名 |
| `Tseg` | 按航线节点、限速和任务条件生成有稳定 ID 的航段 | 支持任意有效起点、返程及剩余航程；实际约束仍需有来源 |
| `Tenergy` | LSTM 预测主推进电机功率，逐时积分成电机侧能耗，提供候选批量预测 | 模型需重新训练和留出验证；未经核实的辅助负载、母线转换和电池侧能耗不能补零 |
| `Tspeed` | 用差分进化（DE）搜索航段速度和时序轨迹，内部批量调用 `Tenergy` 评价候选 | 独立复核距离、时间、速度、功率和能量；有限搜索失败不等于数学无解 |
| `Tmanagement` | 复现导师论文的前向动态规划（FDP），在单组 1、单组 2、双组输出三种模式中分配功率 | 两组电池是研究中的可调度分组，不强求复刻实船分工；参数需核实或标为仿真 |

形成完整方案的依赖为 `Tdata → Tseg → Tspeed（反复批量调用 Tenergy）→ Tmanagement`。`Tspeed` 选定轨迹经过唯一的电机侧到母线侧需求构建位置，再交给 FDP；FDP 反馈可用于有界重搜。统一字段、时间网格、计量边界、失败状态和工件引用以[五工具联调接口 v2](../接口/五工具联调接口_v2.md)为**待冻结目标契约**，不能把各 PR 的局部接口直接视为全项目定稿。

### 数据与验证前提

- 两份 CSV 和一份独立 Excel 均属于同一艘“豫交投001”的研究数据；Excel 不是由那两份 CSV 整理而来，也不对应其两次航行。
- 已确认 CSV 中对地航速单位为**节**，`motor_power` 单位为 **kW**；功率大概率涉及主推进电机，但具体测量位置和电机／母线／电池边界尚未核实。
- 同一时间戳多行等异常作为原始数据清洗问题处理，不因单个异常阻塞整体方案。Excel 的 `capacity` 含义及对应电池尚未确认，不能当成已核实的 SOC 标签。
- LSTM 应按来源或连续时间段留出验证，并与简单功率基线比较；DE 与规则航速、FDP 与状态机需在同一输入与约束下对照。论文或演示系统的数值结果不能当作本研究的实船效果。

### 主智能体与可审查输出

- 主系统采用 LangGraph 的有状态运行图。调用的 API 大模型负责解析船员语言、提出允许的下一步动作、解释工具结果并撰写**第一手自然语言答复**；LSTM 是数值预测模型，不承担对话决策。
- 船员自然语言经 API 模型按固定 schema 抽取；地名简称或错别字结合别名库、候选核对和必要追问处理。船舶实时状态应由有来源的数据适配器读取；现阶段可用历史回放和具名软件仿真。追问由规则确定缺项与候选，模型组织问法。
- 模型提出工具动作，运行时依据当前状态、前置结果、版本和预算决定能否执行。不可行类别由工程规则与工具诊断给出，模型在允许范围内解释、提出调整试算；安全硬约束不能由模型放宽。航中重规划以有来源的实船事件或明确标注的仿真事件触发。
- 每次真实模型动作、规则判定、工具请求及结果、状态变化和船员选择都要可查。界面可折叠展示模型**主动提供的公开决策依据摘要**及调用记录；摘要不冒充模型内部逐词推理。正式答复保存原文、版本和证据包，结构化数值由规则核验；核验失败要明确标识。
- 主图、异常协商、人工暂停恢复、航中重规划和事件／工件存储详见[Agent 图结构计划](../团队资料/02_当前设计/Agent图结构计划.md)。该图计划已讨论并写入方案稿，仍属于目标系统设计，不能据此宣称现有代码全部实现。
