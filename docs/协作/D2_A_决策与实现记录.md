# D2 A决策与实现记录

日期：2026-09-19。负责人：A。范围：软件演示参数冻结、中文任务解析、LangGraph主流程骨架和B的D2集成审查。

## A批准的软件演示规则

- 电池系统总标称容量1567.85kWh；一个箱体、两组电池，演示中每组783.925kWh。
- 初始SOH为90%，总有效容量1411.065kWh；SOH只是演示初值，后续依据充放电吞吐记录趋势。
- 1组推进优先，2组日用优先且可辅助推进；高负荷允许两组同时供电。系统只给出策略建议，不下发实船断电或接触器控制命令。
- 推进功率超过120kW进入协同候选，低于100kW退出；SOC差达到10%进入均衡，缩小至5%退出。
- SOC软件分级：35%关注线、30%规划下限、25%警告、20%临界；20%以下交由操作员和BMS应急处理。硬件断电阈值未知。
- 经济航速约6kn，即11.112km/h；对应演示推进功率90kW、辅助功率30kW、总功率120kW。辅助25%按演示总能耗口径，不作为所有瞬时工况的固定比例。
- 空载吃水1.5m、满载3.2m；半载演示默认2.35m，用户或传感器输入优先。
- 河南省内船闸默认排队等待0h，但仍需计算低速通行；省外等待由人工输入。进闸2km/h、出闸演示2.5km/h。
- 平顶山港、漯河港、周口港和前航船厂作为演示补能节点；额定充电功率未知，完整充电保守按10h或人工输入。
- 环境水文使用历史连续时间片段回放，保留来源、时间范围和随机种子，并标记为历史数据驱动模拟。

机器可读版本位于`configs/demo_policy.yaml`；最低计算采用值位于`configs/vessel_facts.yaml`和`configs/limits.yaml`。

## A的D2实现

- `core/request_parser.py`：确定性解析起终点、SOC、载况/吃水、最长耗时及带标签的完整时间；缺项追问，不猜相对时间和安全参数。
- `core/orchestrator.py`：真实LangGraph状态图，顺序执行Tdata、Tseg、Tenergy、Tspeed、Tmanagement；解析缺项或任一工具失败时停止。
- `main.py`：接受中文任务并输出解析状态、工具结果和节点轨迹。
- 当前默认五工具仍是占位适配器，最终消息会明确说明不能当作航行方案。
