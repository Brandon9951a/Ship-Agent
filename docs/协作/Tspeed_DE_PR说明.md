## 修改内容

按《Tspeed_DE航速优化工具_任务书》与《五工具联调接口_v2.md》，交付差分进化航速优化工具
Tspeed 的 v2 实现；本轮并按《工具构建完善要求》三节完成 Tspeed 的四项个人完善任务。
新增 `research/` 独立模块（仅依赖标准库）：

- `research/contracts/`：v2 机器可读契约（ToolRun 信封、EnergyBatch、PowerDemandSeries、
  SpeedOptimizationResult、失败语义枚举），含 JSON Schema 与合法/非法样例
- `research/demand/builder.py`：**共同需求构建器**（任务书指定由 Tspeed 负责人交付），
  电机侧→母线侧换算与辅助负载合并的唯一执行位置，输出配置哈希与能量守恒检查；
  缺转换依据时 `demand_bus_kw` 保持 null，只做电机侧对照实验
- `research/tspeed/`：轨迹展开器（加减速上限、限速、等待、部分斜坡解析求根、距离积分，
  首段入口按边界条件处理）、DE/rand/1/bin（有效边界、角点初始化、边界修复、精英保留、
  预算与迭代记录）、独立约束检查器（核验精度复算 + 重采样误差 + 速度连续性与边界过渡）、
  工具入口、LSTM 适配层
- `research/migration/v1_to_v2.py`：v1 → v2 显式迁移层（分段平均不逆推逐时、合并 SOC 不拆两组）
- `research/tests/`：验收测试（自带运行器，无需 pytest）
- `research/scripts/`：验收实验、两个负面结果诊断脚本、样例生成
- 文档：`docs/协作/Tspeed_DE_实现与验收记录.md`、`docs/协作/Tspeed_DE_PR说明.md`

演示链路 `schemas/` 与 `tools/`（v1）未改动。

**本轮（《工具构建完善要求》三节）四项任务对应改动：**

1. **定位规则基线差异** → 根因是初始种群缺少**全取下限角点**个体（该角点在能量目标下
   即最优解），DE 曾因此比规则基线差约 18%。修复 `_init_population` 显式加入两个角点，
   并保证单维端点注入不覆盖角点。
2. **定位滚动重规划失败** → 根因是**首段入口速度被限速上限夹取**，而当前速度是请求
   给定的边界条件。修复为首段 `entry_is_boundary=True`，过渡记入 `boundary_transitions`
   并新增两项独立检查。
3. **完善优化器可复核性** → 独立检查由 7 项增至 **10 项**（新增速度连续性、边界过渡、
   能量总量一致性）；搜索轨迹、失败分类、预测次数、耗时均随结果返回。
4. **验证共同需求构建器** → 模块内夹具覆盖：转换只做一次、辅助负载只加一次、
   `kW × s / 3600 = kWh`、配置哈希与来源记录；缺转换依据时母线需求保持未知。

## 验证结果

```powershell
python -m research.tests.run_tests                    # 122 passed / 0 failed
python -m research.scripts.run_tspeed_experiments --output-dir artifacts/tspeed-v2
python -m research.scripts.diagnose_baseline_gap      # 规则基线差异诊断
python -m research.scripts.diagnose_rolling_replan    # 滚动重规划失败诊断
```

- **与精确最优对照**：目标函数在本项目轨迹模型下可精确分解，DP 求精确最优并每次以穷举
  自检；λ=0 时 DE 命中网格最优（偏差 **0.0000%**），λ=10 时 **−0.064%**。
- **完整 17 航段**（81.1 km）：`candidate_found`，母线侧能量 144.41 kWh，历时 14.77 h，
  2440 次评估，**99.1 s**（40.7 ms/次），**10/10 项独立检查通过**。
- **多随机种子**：5/5 找到可行解，目标值离散度 **0.0000%**。
- **规则基线同口径对照**（同一展开、同一后端、同一目标、同一检查器）：
  | 口径 | DE 最优解 | 规则基线 | 差异 |
  |---|---|---|---|
  | 能量 kWh（与 λ 无关） | 142.4769 | 142.4769 | 3.99e-16 |
  | 目标 J（λ=10） | 149.7497 | 149.7497 | 0.0000% |
  即 DE 现在找到与规则基线**相同**的最优解，速度向量逐段一致 `[6,6,5,6,6,5,6,6,5,6,5,4]`。
- **滚动重规划**（剩余 S09–S17、37.4 km、当前速度 7.5 km/h、期限 22.44 h）：
  5 个种子**全部 `candidate_found`**，能量 65.51 kWh、历时 7.04 h。
- **约束场景**：时间过紧、母线功率上限过紧均返回 `search_unresolved`（附首个失败约束、
  违反统计与诊断候选），不返回选定候选；缺转换依据时仅输出电机侧对照实验。

**另修正 2 处对照口径错误**：曾把"含惩罚目标差"表述为节能率、曾拿不同 λ 的目标值对比；
现拆成"能量口径"与"目标口径"两块，各自标明含义。

## 接口与配置

- **新增字段**：`TrajectoryPoint` / `PowerPoint` 增加 `target_speed_kmh`（决策变量）与
  `interval_kind`。原因：一个航段展开为加速/巡航/减速多个区间，斜坡区间的平均速度无法
  反推目标航速，核验阶段需要它精确复原决策向量。
- **新增检查项**：`speed_continuity`（段间与段内速度连续）、`boundary_transition`
  （首段边界速度过渡）、`energy_total_consistency`。
- 单位与边界沿用 v2 约定（内部 km / km/h / kW / kWh，秒为时间单位，SOC 为 0–1）。
- **单一转换位置**：母线侧换算只在 `demand/builder.py` 执行一次，Tspeed 电池约束与
  Tmanagement 读取同一 `PowerDemandSeries` 工件，不各自暗算效率或辅助负载。
- **待裁决参数**（代码不填默认值）：推理/规划步长、长时滚动策略、DE 种群与预算、
  `λ` 与惩罚尺度、电机/母线边界、辅助负载与效率采用值、数值容差、模型适用域。
  实际采用版本请项目负责人裁决，本工具不预设实船默认值。

## 已知限制

- 规则基线对照与滚动案例的结果均为**当前验收用解析模型** `P=c·v³` 上的模型内结论，
  **不是实船节能率**；在当前能量目标与限速下限结构下 DE 与规则基线收敛到同一解，
  因此**不主张 DE 相对规则基线的节能优势**。
- 母线侧效率 0.94、辅助负载 30 kW 为**具名研究假设**，不是实船标定；缺转换依据时
  母线需求保持 `null`。转换参数采用值由项目负责人裁决。
- 未预先填入导师论文的任何精度或效果数值。
- 双电池预算、补能试算未实现（属 FDP 扩展），当前明确返回不支持。
- 是否满足 1800 s 滚动周期，需在 LSTM 接入后按实测耗时判断，本轮不作结论。
- 本轮未做正式验收。
