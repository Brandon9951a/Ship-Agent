# 网站可选航次的智能体稳定性改进：三项任务与验收标准

日期：2026-10-17

工作基线：三工具集成审查分支

验收目标：用户在**原版网站的快捷输入中选择航次**，真实模型调用专业工具；系统最终给出经过复核的仿真方案，或者给出具体的未完成／不可行原因及可操作的修改方向。研究仿真的真实性和实船标定不属于本轮验收。

## 共同范围与完成定义

网站的 9 个可选节点构成 72 个不同起终点组合；2026-10-17 核对 `ui/frontend/app.js` 与 `configs/route_facts.yaml`，这 72 个组合都能映射到正向或返程的连续已登记航段。默认规划使用**解析功率后端**；真实 LSTM 仍只用于显式指定的短轨迹预测，不得将它冒充全航程预测。保留原版网页布局和既有交互，只修正与结果准确展示直接相关的内容。

对每个合法的网站任务，任务必须到达一种明确终态：

1. `research_feasible`：Tdata、Tseg、Tspeed（内部 Tenergy）、Tmanagement/FDP 实际执行，时间、距离、能量、功率、双电池 SOC 和工件归属／哈希经独立复核后展示方案。
2. `infeasible_under_assumptions`：计算已完成且证明当前条件不可行，指出具体约束、所在航段或区间、观测值与限值。
3. `needs_input`：缺少或矛盾的用户条件需要补充，明确指出字段并能在同一任务继续。
4. `solver_unresolved`、`model_unavailable` 等未完成状态：明确是计算预算、服务或模型故障，**不得称为航次不可行**，也不得发布未经复核的方案。

“修改选项”区分两种：已经按修改后的条件完整重算并复核的，才标记为**已验证、可采用**；补能、改变出发时刻或其他需要用户提供新值的，只标记为**待输入、待重算**。不存在经过验证的选项时，说明原因及用户下一步可改的字段。原因分析与可选调整不得重复同一段正文。

## 任务 1：修复独立 Tenergy 预测入口及后端选择

**建议负责人：原 PR #9（Tenergy）组员。优先级：P0。**

### 已确认的问题

主页面 `ui/frontend/research-bridge.js` 提交任务时固定使用 `route_success`，该情景的后端为 `analytic`。但 `research/agent/professional.py` 的独立 `Tenergy` 动作在非 `lstm` 情景直接返回 `not_supported / select_lstm_scenario`。因此用户从普通页面提出独立能耗预测需求，可能在模型正确选择 Tenergy 后仍无法得到预测。Tspeed 搜索中反复调用的解析 Tenergy 是另一条路径，近期任务中的这些候选预测已正常完成，不应混为一谈。

### 实施范围

- 为默认情景的独立 Tenergy 提供真实可调用的**解析预测**：明确输入轨迹或由已识别航段和任务条件构建可校验的预测轨迹；返回功率序列、能量积分、单位、时间范围、后端名称、来源和工件引用。不得用常数答复或模型自行估算冒充工具输出。
- 显式请求真实 LSTM 短时预测时保持现有权重、历史工件和约 20 秒范围；超窗口仍返回 `model_out_of_domain`，不得静默切换后端。
- 让 LangGraph 在预测任务中正确选择情景或后端，前端能显示独立预测结果及失败诊断。保持预测任务与完整规划任务的状态区分。
- 补齐默认情景独立预测、短时 LSTM、超窗口、缺轨迹字段、工件篡改和单位／积分检查。

### 验收标准

1. 从原版网页提交普通“预测该航段能耗”任务：记录到真实模型响应、`Tdata → Tenergy` 调用；默认解析后端返回 `prediction_completed` 和可复算的功率／能量工件，不再出现 `select_lstm_scenario`。
2. 显式 LSTM 20 秒任务仍成功；40 秒任务明确返回域外诊断。两者都展示实际后端，不以解析结果替代真实 LSTM 结果。
3. 预测输入不足时指出缺少的字段，能继续补充；模型无法编造能耗数值或跳过 Tenergy。

## 任务 2：覆盖网站航段的有界求解、失败分类与修改选项

**建议负责人：原 PR #10（Tmanagement/FDP）组员；与 PR #11 组员协作 Tspeed—FDP 交接。优先级：P0。**

### 已确认的问题

2026-10-17 网站任务 `3843f19f-062d-4a41-91a0-1291e3a755ee`（平顶山港→漯河港、15 小时）中，Tspeed 和内部 Tenergy 完成；FDP 在军李船闸→马湾船闸航段到达 `max_transitions=100000`，报 `grid_unresolved`，观测为第 100001 次转移。随后模型连续提出 3 个被 guard 拒绝的动作，最终以 `agent_budget_exhausted` 结束。页面还把同一段失败正文同时放入“原因分析”和“可选调整”。这些是求解预算与失败处理问题，不是证明该航次不可行。

### 实施范围

- 使多航段、返程和长航线具备**有界的自适应求解策略**。可以采用分段／分层计算、经过验证的粗网格重试、状态剪枝或其他方案；明确每轮预算、最大重试次数与精度变化。最终方案仍需原始需求和双电池连续轨迹的独立复核。不能仅无限提高 `max_transitions`。
- 将 `grid_unresolved`、瞬时功率上限、SOC 路径失败、时限失败、输入缺项和真实不可行分开处理。确定的工具诊断由代码映射到下一动作或终态，不让模型在不可执行状态下耗尽无效动作预算。
- 为可调整的任务生成候选：如放宽时限、变更优化目标、调整初始 SOC 或缩短可选航段。**只有重算且通过完整工具链复核的候选才能标记“已验证”**；补能只能要求用户提供新的实测／仿真初始 SOC，不能假装途中充电已计算。
- 页面分别呈现原因、建议、已验证选项与需用户输入的选项；保留原版布局，避免重复文案。失败时不显示伪造的方案指标。

### 验收标准

1. 对网站 9 个节点的 **72 个有序起终点组合**建立自动化清单；每一组合能识别连续航段，并在标准仿真条件下实际跑完工具链，得到复核通过的方案或有具体约束证据的终态；不得仅因固定网格预算而落入 `agent_budget_exhausted`、`tool_error` 或含糊的“无法判断”。测试需记录每组耗时和终态。
2. 对正向、返程、单航段、多航段、全程及两种优化目标取代表性样本；另测短时限、低 SOC、功率限制和等待。不可行时提供航段／区间、实际值、限值与具体修改方向；修改后标为“已验证”的选项必须有独立新工件和完整复核记录。
3. 复测上述平顶山港→漯河港任务：如可在预算内求解则展示方案；若仍超预算，返回 `solver_unresolved`、具体预算与下一步，而不是“航次不可行”或 `agent_budget_exhausted`。页面“原因分析”与“可选调整”不得重复。
4. 所有候选受原任务硬约束约束；模型不能通过改写限速、电池功率、距离或转换效率制造成功。

## 任务 3：服务存活、进行中任务恢复与结果一致性

**建议负责人：原 PR #11（Tspeed／联调）组员；负责 LangGraph 运行时和网页任务恢复，必要时协调服务部署者。优先级：P1。**

### 已确认的问题

本地网站服务曾关闭，用户无法打开页面。`research/agent/runtime.py` 在启动时把所有 `running`／`queued` 任务直接改成 `process_interrupted`，虽已保存 SQLite 检查点和工件，却不能继续进行中的求解。后台线程池仅在当前服务进程内管理任务。等待用户补充的任务已有恢复机制，但计算中的任务未达到同等恢复能力。

### 实施范围

- 为本地验收提供明确的启动、健康检查、异常重启和日志查看方式；若部署到 Render，沿用其进程管理，不在网页内伪造“在线”。
- 为 `queued`／`running` 任务建立可重入的执行策略：重启后从检查点继续，或从最后一个已验证的工件安全重试；保证任务归属、revision、输入快照、动作 ID 和工件哈希一致。重复执行不能重复发布方案或把旧版本结果混入新任务。
- 为长任务设置队列上限、任务级超时、取消／重试语义和可观察的阶段状态；网页刷新或重新登录后取回同一任务的状态、事件和结果。
- 服务／模型确实无法恢复时返回具体故障状态和可重试操作，不发布未经复核的方案。

### 验收标准

1. 分别在排队、Tspeed 搜索和 FDP 求解阶段中断服务并重启；同一任务继续或安全重试后到达明确终态，事件与工件无重复冲突；不能一律标为 `process_interrupted`。
2. 中断时刷新页面、恢复登录并重开历史任务，能够看到同一任务的最新状态和最终答复；等待补充任务的同一回答只应用一次。
3. 连续提交多任务时服务仍响应 `/healthz`，任务有排队和超时边界；故障可由日志和事件定位，模型／工具错误不显示为航次约束不可行。

## 联合验收与交付规则

- 三项分别提交独立 PR，**基于并指向远程三工具集成审查分支**；不要直接并入 `main`。各 PR 附运行命令、关键任务 ID、模型标识、工具调用记录、工件引用、断言结果和仍有限制。
- 联合验收以原版网站完成：72 个可选起终点组合的标准运行，典型失败条件和修改选项、独立能耗预测、短时 LSTM、模型不可用、服务重启与刷新。自动化模型可做回归，但至少一轮使用真实配置的 DeepSeek API；不得以脚本模型结果代替真实调用验收。
- 本轮“成功”的定义是**软件仿真与工具链跑通**。不要求上游船端数据、真实载况标定或正式航行批准；这些限制要保留来源标记，但不能成为默认可选航段任务因代码缺陷而失败的借口。
- 三份 PR 联合复核通过并由项目负责人验收后，再按项目流程决定是否并入远程 `main`。
