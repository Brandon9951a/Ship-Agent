## 3. 发给 B/C 的操作说明

### 第一步：接受邀请

1. 登录被邀请的 GitHub 账号，接受仓库邀请。
2. 打开共享仓库，确认能看到 README、源码和团队资料。
3. 向 A 回报自己的 GitHub 用户名与“邀请已接受”。

如果打不开私有仓库，先核对登录账号和邀请接受状态，不要将仓库改为公开来解决。

### 第二步：克隆仓库

安装 Git 和 Python 3.10 或以上。下面命令假设成员尚未克隆仓库，在自己选择的工作目录执行：

```powershell
git --version
python --version
git clone https://github.com/Brandon9951a/Ship-Agent.git
cd Ship-Agent
git status --short --branch
```

已经克隆的人直接进入现有克隆目录。确认没有未提交修改后，切换 main 并执行：

```powershell
git switch main
git pull --ff-only
```

若有未提交修改、拉取冲突或分支不一致，先发给 A 确认，不执行强制覆盖或删除重建。

### 第三步：安装与运行

Windows PowerShell，在仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m core
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m pip check
```

已存在可用 .venv 时不用重复创建。直接调用虚拟环境中的 Python，无需激活，因此通常无需修改 PowerShell 执行策略。

预期：

- main.py 输出状态响应。
- core 入口输出五个工具的占位结果。
- 当前基准提交有两个测试，应全部通过；后续代码变化可能增加测试数量。
- pip check 无依赖冲突。

macOS/Linux 成员使用 `python3` 创建环境，虚拟环境解释器路径为 `.venv/bin/python`，不要使用 Windows 的 Scripts 路径。

### 第四步：验证分支推送权限

B 创建自己的分支：

