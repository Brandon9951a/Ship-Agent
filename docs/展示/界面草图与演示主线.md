页面必须根据契约状态渲染：`need_clarification` 显示缺失字段和追问；`infeasible` 显示分类和原因；`failed` 显示失败与回退；只有完整 `ok` 结果显示成功数值。未知字段显示“未知/待核实”，不显示为 0。

## 演示主线

1. 输入一条由 B 核准的正常子航线，展示 Tdata 来源、Tseg 航段、能耗和 SOC 结果。
2. 输入时间不可行条件，展示 `infeasible` 原因和工具试算方向；用户选择后再进入重算流程。
3. 输入 SOC 不足条件，展示安全拒绝和有依据的调整建议；若充电能力未知，明确提示不能承诺补能可行。
4. 补演缺参、返程/子航线和工具失败，确认状态、追问和失败原因不会被伪装成成功。

## 数据展示约束

- 距离使用 km，速度使用 km/h，时间长度使用 h，能量使用 kWh，SOC 使用百分比展示但内部传 0-1。
- 结果数字只能来自通过校验的工具字段。
- 图表等到 B 提供冻结结果后再制作。
- UI 草图不是已实现页面，也不是测试通过证明。
